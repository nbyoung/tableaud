# What a person tests at validate

No browser, screen reader or phone runs on the host that writes and tests this design. Each row is a claim the design rests on reasoning for, the test a person runs at the `validate` gate (🌍), and the fix the design names if the test fails. The daemon serves the tooling plan; the export is `tableaud export --out <dir>` opened from the file system. Run V3 to V8 on both.

| # | Claim | The test | If it fails |
|---|---|---|---|
| V1 | The keyboard alone reaches and works every control | From the address bar press Tab: the skip link shows first; Enter on it, then Tab, lands on the first control of `main`. Tab through the global tableau: every stop shows a ring; Enter on "*n* rows beneath" draws the rows; Enter and Space open a fold; Shift+Tab goes back; no stop traps | The rule the stop breaks, K1 to K4 |
| V2 | After an expander or the authority filter swaps the page, the focus stands on the same control | With script on, press Enter on "*n* rows beneath": the link now reads "fold the *n* rows beneath" and holds the focus; press Enter again | A8 fails: the third job of [`focus.js`](focus.js), decision 6 |
| V3 | A refresh keeps the focus of a fold, a button, a checkbox and the grid, and drops that of a plain link | Put the focus on a summary, change a status file in the repository, wait one poll: the focus stays. Repeat on a task id: the focus goes to the top of the page | For the plain link, decision 6's alternative |
| V4 | The grid scrolls sideways under the keyboard | At a window 320 CSS pixels wide, Tab to the grid: the ring surrounds it; the arrow keys scroll it; the task column stays in view | Rule K2 on the scroller; the sticky rule goes if the column covers the cells |
| V5 | A table other than the grid scrolls sideways under the keyboard where it overflows | At 320 pixels open the task view's junction table and the audit's findings: where one overflows, Tab to a link or a fold inside it and press the arrow keys | Decision 8's alternative: every scroller takes the grid's four attributes |
| V6 | A screen reader says names, never symbols | NVDA with Firefox and VoiceOver with Safari, on the global tableau, the task view and the gate definition: a cell reads its column, its row and "stalled, blocked"; no emoji name sounds; a row header says "level 2"; the grid announces its caption as the name of a group; an expander says its task; a day of the history reads its heading inside the summary (9a9c); listen to how `at_risk` sounds | The partial `syms`; for `at_risk`, the finding on state names |
| V7 | Both themes follow the system with no flash, and the controls follow too | Switch the system between light and dark and reload each view; look at the checkboxes, the button, the brief's text area and the scroll bars | The `color-scheme` meta and rule, C5 |
| V8 | A state reads without colour | View the global tableau in greyscale, or through a simulation of red-green colour blindness: tell nominal, at risk and stalled apart by the line under each; then turn on a forced-colours mode and check the lines, the marked cells and a row a link targets | Decision 3's alternative: the state's word in the cell |
| V9 | Every view reads at phone width | On a phone, or at 320 pixels: none of the ten views scrolls sideways as a page; the authority's rows stack title over assignee; commands wrap inside their block; then zoom a desktop window to 200 and to 400 per cent, and set the browser's font size to 24 pixels | Rule P3 for the element that overflows; decision 7's alternative for the grid |
| V10 | A touch reaches every control | On a phone tap each task id, each summary, each checkbox by its label: none needs a second try; each target measures 24 CSS pixels or more in the inspector | Padding on the control, in the narrow block |
| V11 | Nothing moves | With "reduce motion" on and off, expand a row and open a fold: nothing slides or fades | Rule M1 |
