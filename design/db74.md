# Design db74: Progressive disclosure

This task delivers what arrives open on a page and how a reader moves from there: the opener that follows the role, the rows a tableau opens on, the address of every next state of expansion, the column choice as a form, and the last change the script needs. Most of the task's description already stands: [`49ce`](49ce.md) fixes `open`, `columns`, the store and the landing by role, [`438a`](438a.md) the `Opener`, and [`44bf`](44bf.md) the grid, the fold links and the form's markup. This design confirms or amends each of those rows and adds what remains. Six choices shape it:

- **The role chooses the page, and the page chooses the rows.** `/` leads the owner to the global tableau and a holder of any other role to their corner, as built. At an address every reader then sees the same rows: the root and its children on the global tableau, the task and its children on the task form, the whole spine on the person form (decisions 1 and 2).
- **A state of rows has one spelling**, and the entry state has the shortest: the address without `open`. `Unfold` computes the rows drawn and each fold link, so that an expand followed by its collapse returns the first address.
- **The opener reads a focus that the adapter names.** An `Opener` sees a view, a class and an id, which cannot say "the viewer's own section". `Env.Focus` names those folds, and `ByRole` opens them (decision 3). An observer and the export keep the level's arrival, byte for byte (decision 4).
- **The frame gains two controls**: the level as four plain links, and a second link to the page that states what the viewer's role and identity otherwise supply (decisions 5 and 6).
- **The column choice is the form alone**, with one link back to the default window; the script stores a submit only when the reader changes a box (decision 7).
- **The daemon computes no window.** tablo's default passes through (A4).

### The role in force and the opener

```go
// roleOf returns the role in force on a page: the role the address states,
// else the viewer's first, else "observer".
func roleOf(p *Page) string

// ByRole opens the folds of a page by more than the level: by the role in
// force, by the focus an adapter names with Env.Focus, and by the open rows
// the address states. Every fold it has no rule for opens as ByLevel(Level)
// does, and so does every fold until the adapter names a focus.
type ByRole struct {
	Level Level           // the level of the page
	Role  string          // the role in force
	Rows  bool            // the address states the open rows of the contextual tableau
	Focus map[string]bool // the fold ids the adapter names; nil until it names any
}

// openerOf returns the opener of a page; envOf asks it in place of ByLevel(levelOf(p)).
func openerOf(p *Page) Opener

// Focus returns e with the folds of ids named as the focus of the arrival. An
// opener that reads no focus, ByLevel or openAll, stays as it is. An adapter
// calls it once, before it asks for a fold; Focus() with no id names an empty
// focus, which is not the same as none.
func (e Env) Focus(ids ...string) Env
```

**A role's arrival applies when the address states no level and the level is not glance.** So it never applies to an observer, to `role=observer`, to the export or to an address with `level`: those pages open by `ByLevel(levelOf(p))`, as on `main`. Where it applies, `openerOf` returns:

| View | Opener | Arrives open |
|---|---|---|
| `tableau` | `ByLevel(Glance)` | Nothing: the grid on its entry rows, every note and every provenance closed, for every role (decision 1) |
| `context` | `ByLevel(levelOf(p))`; with `open` in the address, for every viewer and every level, `ByRole` with `Rows` | As on `main`: each block and `d-wider` from detail on. With `open`, `d-wider` also, since the address names its rows |
| `authority` | `ByRole` | `detail` and `kids`: the focus alone |
| `assignment` | `ByRole` | `detail`, a person's section: every section for the owner, the focus for any other role. `group`: the focus |
| `queue` | `ByRole` | `detail`: the focus |
| `blockage` | `ByRole` | `detail`: every fold for the owner, the focus for any other role |
| `gates`, `task`, `history`, `audit` | `ByLevel(levelOf(p))` | As on `main`; the mockups ask no more of these four |

Every class the table does not name opens by level, so a `prov` stays closed and a `fold`, a `columns` never open. A part still renders under `openAll`.

**The focus**, which the adapter of each view names from tablo's data and the viewer's email, `e.Page.Viewer.Email`:

| View | The adapter calls `e.Focus` with |
|---|---|
| `authority` | `AuthorityFocus(tasks, viewer)`. e2b6's rule for the filter still opens the kept path |
| `assignment` | The anchor of the viewer's section and of the section the `person` parameter names; and, in every section, the id of each group whose `Next` is above zero |
| `queue` | The fold of the first item on the page, when the queue's person is the viewer and the address names no `brief`; otherwise no id. 44bf's rule still opens the item `brief` names |
| `blockage` | `d-cause-N` of each cause the viewer resolves or that holds a task the viewer is assigned or contributes at next, with every `h-N-ID` inside it; and `d-next-ID` of each such task among those that wait (A6) |

```go
// Holder is one task as the focus of the authority tree reads it.
type Holder struct{ ID, Parent, Assignee string }

// AuthorityFocus returns the fold ids the authority tree opens for a viewer,
// from the tasks in display order. The tops are the tasks the viewer is
// assigned that stand under no other task of the viewer's; a viewer assigned
// none takes the root. The focus holds the detail t-ID of each top, the
// children k-ID of every ancestor of a top and of each top itself, and the
// children of every parent beneath a top unless its children are all leaves
// with its own assignee. The ids stand in display order, t- before k-.
func AuthorityFocus(tasks []Holder, viewer string) []string
```

On the weather station the owner `ada@example.org` gets `t-a1c0`, `k-a1c0`, `k-4e2b`; the authority `ben@example.org` gets `k-a1c0`, `t-4e2b`, `k-4e2b`; `dan@example.org`, who holds one leaf, gets `k-a1c0`, `t-3c5d`. That is `authority.html`'s sentence: the owner arrives "with the root's detail open", a parent of like leaves "folds to a count", and an authority arrives "with the subtrees they have authority over unfolded and the chain above their own tasks open".

Until an adapter names a focus, `ByRole` opens exactly what `ByLevel` opens, but for `d-wider` under `Rows`. No adapter stands on `main`, so no fixture, no golden page and no existing test changes with this task.

### The rows a tableau opens on

```go
// Entry returns the rows a grid opens on when the address states no open set.
// top is the first row of the grid: the root, or the task of the task form;
// spine lists the ancestors of the person's tasks, for the person form.
func Entry(p *Page, top string, spine []string) Unfolded

// TreeRow is one row of a grid as the open set reads it: its id and its
// parent's. A row whose parent stands in no row of the grid is a top row.
type TreeRow struct{ ID, Parent string }

// Unfold resolves the open state of the grid whose rows stand in display
// order: the open set of the address when it states one, else entry. An id
// that names no parent of the grid drops out, and so does a parent beneath a
// closed one, so that a state has one spelling. With entry.Branches the grid
// draws its first row and that row's children, whatever the address states.
func Unfold(p *Page, rows []TreeRow, entry Unfolded) *Unfolding

// Draws reports whether the grid draws the row: every ancestor of it is open.
func (u *Unfolding) Draws(id string) bool

// Open returns the open parents, sorted by id.
func (u *Unfolding) Open() []string

// Controls returns the control of a row's fold: expand, the address that
// draws the rows beneath it, or collapse, the address that folds them and
// every open row beneath; both nil for a row with no row beneath it in the grid.
func (u *Unfolding) Controls(id string) (expand, collapse *Control)

// Opened returns the address of this page with exactly the rows of ids open.
// No id is the address that states the empty set, open=.
func (p *Page) Opened(ids []string) string
```

| Page | `Entry` |
|---|---|
| `/tableau` | `{IDs: [root]}`: the root and its children, whoever reads. With `level=detail` or `level=provenance` in the address, `{All: true}`: every row, as VIEWS.md's detail states. In the export, `Branches` also |
| `/context?task=T` | `{IDs: [T]}`: the task and its children, at every level |
| `/context` and `/context?person=E` | `{IDs: spine}`: every ancestor of the person's tasks, so the person's tasks and their siblings show under their parents |

The entry never reads the viewer. A contributor "opens at the parents of their tasks" because `/` leads them to the person form of themselves, and the person form of anybody opens at that person's spine. So an address without `open` shows every reader the same rows at the same commit.

**The adapter calls `Unfold` once per page**, for the grid that holds the hierarchy: the tableau's `Grid`, the task form's `Grid`, the person form's `Wider.Grid`. It draws the rows `Draws` accepts and gives each `Row` the pair `Controls` returns. The person form's first grid, the person's own tasks, is flat and takes no control.

**The address arithmetic**, which `Controls` holds and [`cases.json`](db74/cases.json) fixes:

- The next state of an expand is the open set with the row; of a collapse, the open set without the row and without every open row beneath it.
- A next state equal to the entry state takes the address without `open`. Every other takes `Opened`, which sorts the ids; the empty set reads `open=`.
- Every other parameter of the page stays; `part` goes. `Swap` is on.
- With `Branches`, a child of the first row that has rows beneath it takes `&Control{Href: "#branch-ID"}` as expand, and no other row takes a control (44bf decision 4). On any other page without scripts no row takes a control.

`Page.Self("open", "")` removes the name, so `Self` cannot write the state "every row folded"; `Opened` exists for that (finding C1).

### The column choice

```go
// GateChoice is one gate of the project as the column choice reads it, in
// gate order: its key, whether the page shows its column, and the count of
// tasks whose current gate it is.
type GateChoice struct {
	Key   string
	Shown bool
	Count int
}

// ColumnsOf returns the column choice of a tableau page, for Grid.Control of
// its first grid, or nil in the export, which draws none.
func ColumnsOf(e Env, gates []GateChoice) *ColumnsForm
```

| Field | `ColumnsOf` sets |
|---|---|
| `Fold` | `e.Fold("columns", "columns", "", "")`: it never arrives open |
| `Action` | The route with no query: `/tableau` or `/context`. A `GET` form replaces the query, so the form restates what it keeps |
| `Hidden` | In the order of `web.Order`: `project`, `ref`, `task`, `person`, `role`, `level`, each where the view reads it and the address states it, and `open` where the address states it, even empty. Never `columns`, `window`, `historical` or `part` |
| `Name`, `HistName` | `columns` and `historical`: the names 49ce's parser reads, repeated `columns` included (49ce, L9) |
| `Gates` | One `ColumnChoice` per gate, in gate order: the symbol from the legend, `Checked` where the page shows the column |
| `Hist`, `Shown`, `Total` | `Params.Historical`; the gates shown; every gate |
| `Reset` (new) | A `Control` with `Swap` on, to the page's address without `columns`, `window` and `part`, when the address states `columns` or `window`; nil when the page shows the default window |

`gridcolumns` in `shared/grid.html` gains one line after the button:

```
{{with .Reset}}
<a href="{{.Href}}" data-columns=""{{template "swap" .}}>Return to the default window</a>{{end}}
```

The seven fixtures hold no `Reset`, so no golden page changes. A reader hides a column by clearing its box and shows one by setting it; the form submits the whole list, which is the absolute list the address and the store hold. A submit with no box set states no `columns`, and the page shows the default window. A column outside the list folds to a count as a column outside the window does: one notation serves both (438a decision 1), and prototype db74's separate marker for a hidden column does not land. The `historical` switch travels in the address and is not stored.

### The script

[`db74/tableaud.js`](db74/tableaud.js) changes the `submit` listener and nothing else. On `main` every submit of `form.columns` stores the boxes set. A reader on the default window who sets "Show the marks of historical junctions" and submits therefore stores today's window as a choice, and the window stops following the project. The listener now compares each `input[name="columns"]` with its `defaultChecked`: when no box differs from what the page drew, it stores nothing (decision 7). The file has 78 lines, under the eighty of 49ce decision 4. It adds no dependency and no build step, so the README's policy on vendored assets holds as it stands.

The script needs nothing else from this task. The `Reset` link carries `data-columns=""`, which the click listener on `main` reads as "clear the store". A fold link keeps the page's `columns`, since `Unfold` builds it from the page's own parameters. The level links are plain, with no `hx-boost`, so the second job of the script does not restore the folds they change (49ce, Controls).

### Two controls in the frame

```go
// Levels returns the four entries of the level control: "by role", the
// address that states no level, then the three levels. The entry the address
// states is Current. A page with no scripts or with an error has none.
func (p *Page) Levels() []NavItem

// Share returns the address that opens this page for another viewer as this
// viewer sees it: the page's own address with the role in force and, on the
// two views whose person defaults to the viewer, the viewer as person. It
// returns the empty string when that address is the page's own, on a page
// with no scripts and on an error page.
func (p *Page) Share() string
```

`base.html` gains, after the context line and inside `header.site`:

```
{{- with .Levels}}
<p class="levels">Level:{{range $i, $l := .}}{{if $i}} ·{{end}} <a href="{{$l.Href}}"{{if $l.Current}} aria-current="true"{{end}}>{{$l.Label}}</a>{{end}}</p>
{{- end}}
```

and its footer reads `… <a href="{{.Self}}">the link to this page</a>{{with .Share}} · <a href="{{.}}">the link that opens it as you see it</a>{{end}}`. The sheet's joined part gains two rules, in the shared block's tokens:

```
p.levels { color: var(--muted); font-size: .875rem; margin: .25rem 0 0; }
p.levels a[aria-current="true"] { color: var(--fg); font-weight: 600; text-decoration: none; }
```

No page on `main` offers a way to another level, though 49ce names "a `level` link" and VIEWS.md has HTML "fold and unfold" between levels: `Levels` is that link. `Share` answers the description's last sentence. `/context` shows the viewer's own corner and opens at the viewer's level, so the bare address shows its receiver another page; `Share` on Ben's corner is `/context?person=ben@example.org&role=assignee`, which opens Ben's corner at Ben's level for anyone.

### What has an address

| State | In the address | A shared link |
|---|---|---|
| The rows a tableau draws | `open`, or its absence for the entry | Exact while the tasks stand; an id the project loses drops out |
| The columns | `columns` or `window`, or their absence for tablo's default | Exact with `columns`; without it the window follows the project |
| The historical marks | `historical=on` | Exact |
| The level | `level`, or its absence for the role's | Exact with `level`; `Share` states the role |
| The person in focus | `person`, or the viewer on `/context` and `/queue` | `Share` states the person |
| One lazy fold | `part=NAME:KEY`, the fold's own fallback link (438a) | Exact |
| A `details` a reader opens by hand | Nothing. The script keeps it across a swap (49ce) | Not carried |
| The focus of an arrival | Nothing: it follows the reader's own email | The receiver's own |

e2b6 leaves to this task whether an address names open nodes of the authority tree. It does not: `open` belongs to the two tableaux, a tree of native `details` keeps its state in the browser, and a link to one node is the node's part.

### The static export

| | In the bundle |
|---|---|
| Rows | The global tableau draws the root, its children, and each branch whole in a native `details` (44bf decision 4). The person form draws its whole spine, the task form the task and its children. No row carries a control but the anchors to the branches |
| Folds | Every page opens as an observer's at glance: `ByLevel(Glance)`, which opens `kids` and nothing else, with every body in the page (`Inline`). This confirms 6160 A12; `ByRole` never applies |
| Columns | The default window, each fold with its count; `ColumnsOf` returns nil |
| The frame | No level control and no second link: `Levels` and `Share` return nothing without scripts |
| Script | None, and none would add anything: 6160's check refuses a `script`, and its table gives the bundle the default window alone. Prototype finding 3's script that hides columns in an export does not land |

The bundle's pages therefore read with scripts off, because they hold none. The daemon's pages read with scripts off too: each control of this design is a link or a `GET` form that loads the page of the next state, a lazy fold shows its fallback link, and only the stored choice and the folds kept across a load are lost. No browser runs here; see [Tests](#tests).

### The prototype's seven findings

| # | Finding | Settled |
|---|---|---|
| 1 | The data must state the owner, the role and a parent id per row | A1 and A2: tablo names the viewer's roles, owner first (49ce A5), and each row's parent (44bf A5). The daemon derives no role |
| 2 | Is `open` relative, as the columns were? | Absolute, as 49ce fixes it. The entry state alone is relative: it is the absent `open` |
| 3 | The stored choice costs a redirect and a flash; a script in the export | Settled by 49ce decisions 4 and 5: the redirect stands, and its look in a browser falls to `validate`. No script in the export |
| 4 | A link means "default plus differences" once the project moves | Dissolved by 49ce decision 5: `columns` is absolute. The table above says what follows the project |
| 5 | A contributor cannot expand a parent outside the corner | The row keeps its plain count (44bf). A fold link changes `open` on its own page and nothing else; the nav's Tableau entry leads to the whole tree |
| 6 | Whose next gates the corner's window spans | tablo's to compute (A4). The daemon passes `Window: -1` and draws the columns that come back |
| 7 | The owner who contributes has no role switch | The nav holds both places, Tableau and My corner, and `role` reads any page as a role the viewer names. tablotui's `R` moves between places; here the nav does |

**Kept from the prototype:** the open rows as ids in the address; one spelling per state, with a closed row's descendants gone; the entry state as the shortest address; a shared address that wins over the store, since reading is not deciding; a server that reads nothing but the address; the walk over every control as a test (T4). **Dropped:** `as`, `hide` and `show`; `DefaultWindow` and the fold counts the prototype computes; the hidden column's own marker; `RoleOf` over three views; `cols.js` and its one key; the expand-all and collapse-all controls, for which `level=detail` and `open=` stand; `--window`, `--render` and `--fragment`.

## Conformance to the texts

- **[VIEWS.md, Levels](https://github.com/nbyoung/tableaux/blob/main/VIEWS.md#levels).** "A role names the level a view opens at": `levelOf`, unchanged. "HTML and the terminal fold and unfold": the level control and native `details`. "`level` … overriding the role's": an address with `level` opens by `ByLevel` alone and reads no focus.
- **[VIEWS.md, Global tableau](https://github.com/nbyoung/tableaux/blob/main/VIEWS.md#global-tableau).** Glance, "the rows to depth one", is the entry; detail, "every row", is `level=detail`. **Two texts disagree here.** Levels opens detail "for the roles the view serves", and the owner is one; `tableau.html` says "the page opens on the root and its children", PLAN.md "the root collapsed; expand down the hierarchy", and tablotui's f394 decision 6 the same. The design follows the three (decision 1).
- **[VIEWS.md, Contextual tableau](https://github.com/nbyoung/tableaux/blob/main/VIEWS.md#contextual-tableau)** and `context.html`, "a contributor arrives at the person form below, with the parents of their tasks open": `landing`, then `Entry`'s spine.
- **[PLAN.md, Views](https://github.com/nbyoung/tableaux/blob/main/PLAN.md#views).** "The window is a default the view computes, not a policy a role imposes": no role enters `source.Request`'s window, and the daemon computes none. "A link to an HTML page carries the columns it shows": 49ce's `columns`, and `Share` for what the viewer supplies.
- **The mockups' arrival notes.** `authority.html`, `assignment.html`, `queue.html` and `blockage.html`: the `ByRole` table. `gates.html`, `task.html`, `history.html`: `levelOf` already draws them. `audit.html` has an authority arrive "with the groups open over that authority's subtree"; the audit opens by level, and the `task` parameter narrows it to a subtree (decision 8).
- **The task's description is scaffolding where a ruling passed it.** "The root collapsed" reads as the tree collapsed to the root's level, as `tableau.html` draws it; the root alone is `open=`. "Hides or shows any column" is the form of 438a's finding C13, not `tableau.html`'s buttons. Both stay as written.
- **VIEWS.md is silent** on which of a viewer's several roles decides the level; the daemon takes the first tablo names (49ce), and `role` states another.
