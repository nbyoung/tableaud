# Design db74: Progressive disclosure

This task delivers what arrives open on a page and how a reader moves from there: the opener that follows the role, the rows a tableau opens on, the address of every next state of expansion, the column choice as a form, and the last change the script needs. Most of the task's description already stands: [`49ce`](49ce.md) fixes `open`, `columns`, the store and the landing by role, [`438a`](438a.md) the `Opener`, and [`44bf`](44bf.md) the grid, the fold links and the form's markup. This design confirms or amends each of those rows and adds what remains. The owner reviews it twice on 2026-10-07; [Decisions at review](#decisions-at-review) holds the rulings of both reviews, and the text agrees with each. Seven choices shape it:

- **The role chooses the page, and the page chooses the rows.** `/` leads the owner to the global tableau and a holder of any other role to their corner, as built. At an address every reader then sees the same rows: the root and its children on the global tableau, the task and its children on the task form, the whole spine on the person form (decisions 1 and 2).
- **A state of rows has one spelling**, and the entry state has the shortest: the address without `open`. `Unfold` computes the rows drawn and each fold link, so that an expand followed by its collapse returns the first address.
- **The opener reads a focus that the adapter names.** An `Opener` sees a view, a class and an id, which cannot say "the viewer's own section". `Env.Focus` names those folds, and `ByRole` opens them (decision 3). An observer and the export keep the level's arrival, byte for byte (decision 4).
- **The frame gains two controls**: the level as four plain links (decision 5), and a second link to the page as the viewer sees it. **One new parameter, `as_seen_by`, names the person whose arrangement a page draws.** Where the address states it, that person and not the viewer gives the role in force, the person of the corner and the queue, the level and the focus. It is presentation and never identity: the viewer stays the connection's, and the frame names both people (decision 6).
- **The audit takes a focus by resolver**, and its address carries `minimum` (decision 8).
- **The column choice is the form alone**, with one link back to the default window; the script stores a submit only when the reader changes a box (decision 7).
- **The daemon computes no window.** tablo's default passes through (A4).

### `as_seen_by`: the person a page is seen by

```go
// SeenBy returns the person whose arrangement the page draws: the one the
// address names with as_seen_by, with the roles tablo finds for that email,
// else the viewer. The viewer stays the connection's.
func (p *Page) SeenBy() source.Viewer

// AsSelf returns the address of this page without as_seen_by when the address
// names a person other than the viewer; else, and on an error page, "".
func (p *Page) AsSelf() string

// Unheld reports whether as_seen_by names a person other than the viewer who
// holds no role in the project; a viewer who holds none is never unheld.
func (p *Page) Unheld() bool
```

`as_seen_by=<email>` is the first parameter of two words, and the owner chooses the name. `Params.SeenBy` holds it, and `Page.Seen`, a `*source.Viewer`, holds that person with the roles tablo finds, nil where the address names none. It is presentation and never identity: `Page.Viewer` stays the connection's (49ce, "Viewer and role"; `--as`), `source.Request.Viewer` stays the viewer, and the daemon writes nothing either way. It is not prototype db74's `as`, which changes the identity and does not land.

| What follows the reader | With `as_seen_by` in the address | Without it |
|---|---|---|
| The role in force, where the address states no `role` | That person's first role: `roleOf` | The viewer's first role |
| The level a role arrives at | `levelOf`, through `roleOf` | As on `main` |
| The person of `/context` with no task and of `/queue`, where the address states no `person` | That person: `request` sets `Request.Person` | tablo's default, the viewer |
| The focus, on each of the five views that have one | That person's email | The viewer's email |
| The page `/` leads to | The page that person's first role lands on, with `as_seen_by` kept | The viewer's |

The choices the ruling leaves to this design:

- **An email that holds no role reads as an observer.** `ParseQuery` checks the syntax of an email, as it does for `person`, and no more; a malformed value and a name given twice are a `400`. The server asks `Source.Describe` for the email's roles, at the page's project and ref, and tablo answers `observer` alone (A12). The page then arrives at glance, and the corner and the queue of that person hold no row, as tablo answers for a person with no task. It is no `404`: the person may hold a role at another ref. The frame then says so in words and on the highlight tint: the notice reads "as seen by EMAIL, who holds no role in this project", still in `strong`, and the context line takes the class `norole`, which paints `--mark`. `Unheld` decides both, so the highlight belongs to `as_seen_by` alone: a viewer at the keyboard who holds no role reads "viewer EMAIL, observer" as on `main`, with no highlight.
- **Its place in `web.Order`** is after `person` and before `role`: `project`, `ref`, `task`, `person`, `as_seen_by`, `role`, `level`, …. An address then reads who, as seen by whom, in which role, at which level. **Every control of the page restates it**: the form of the column choice holds it among its hidden fields, in that order; the four level links, each fold link and the `Reset` link keep it, since each comes from `Page.Self` or from the page's own parameters.
- **A link to another view carries it**, as it carries `role`: `Page.To` and `serve.sticky` keep both, so a reader who follows the nav stays in the same person's arrangement, and a `role` that travels never parts from the person it qualifies. The notice in the frame is the way out. **The title of the page carries it too.** On `main` the frame builds the title in `Page.Title` (`page.go`), "VIEW · PROJECT", which the `document` template of `base.html` writes in `title` (49ce). `Title` now adds " · as seen by EMAIL" where `AsSelf` is not empty, so a reader with several tabs sees which are borrowed; 5a2f's F1 asks only that a title exists.
- **The frame says so where the two differ.** After the viewer, the context line reads `· <strong>as seen by ben@example.org, assignee</strong> · <a id="as-self" href="…">see it as yourself</a>`, with the first role of that person and `AsSelf` as the address. Where `as_seen_by` names the viewer, the frame and the title name one person and add nothing.
- **The export states none.** It has no viewer, offers no second link and draws no notice; its linker reads the view, the task, the person and the project of a link and nothing else, so no page of a bundle exists for an `as_seen_by`, and every page stays the observer's (6160 A12).

### The role in force and the opener

```go
// roleOf returns the role in force on a page: the role the address states,
// else the first role of the person the page is seen by, else "observer".
// levelOf reads it in place of the viewer's first role.
func roleOf(p *Page) string

// ByRole opens the folds of a page by more than the level: by the role in
// force, by the focus an adapter names with Env.Focus, and by the open rows
// the address states. Every fold it has no rule for opens as ByLevel(Level)
// does, and so does every fold until the adapter names a focus.
type ByRole struct {
	Level Level           // the level of the page
	Role  string          // the role in force
	Rows  bool            // the address states the open rows of the contextual tableau
	Focus map[string]bool // the fold ids the adapter names; nil until it names any
}

// openerOf returns the opener of a page; envOf asks it in place of ByLevel(levelOf(p)).
func openerOf(p *Page) Opener

// Focus returns e with the folds of ids named as the focus of the arrival. An
// opener that reads no focus, ByLevel or openAll, stays as it is. An adapter
// calls it once, before it asks for a fold; Focus() with no id names an empty
// focus, which is not the same as none.
func (e Env) Focus(ids ...string) Env
```

**A role's arrival applies when the address states no level and the level is not glance.** So it never applies to an observer, to `role=observer`, to the export or to an address with `level`: those pages open by `ByLevel(levelOf(p))`, as on `main`. Where it applies, `openerOf` returns:

| View | Opener | Arrives open |
|---|---|---|
| `tableau` | `ByLevel(Glance)` | Nothing: the grid on its entry rows, every note and every provenance closed, for every role (decision 1) |
| `context` | `ByLevel(levelOf(p))`; with `open` in the address, for every viewer and every level, `ByRole` with `Rows` | As on `main`: each block and `d-wider` from detail on. With `open`, `d-wider` also, since the address names its rows |
| `authority` | `ByRole` | `detail` and `kids`: the focus alone |
| `assignment` | `ByRole` | `detail`, a person's section: every section for the owner, the focus for any other role. `group`: the focus |
| `queue` | `ByRole` | `detail`: the focus |
| `blockage` | `ByRole` | `detail`: every fold for the owner, the focus for any other role |
| `audit` | `ByLevel(levelOf(p))` for the owner; `ByRole` for any other role | The owner: every group down to its provenance, as on `main`. Any other role, `detail`: the focus, and every group where the adapter names none (decision 8) |
| `gates`, `task`, `history` | `ByLevel(levelOf(p))` | As on `main`; the mockups ask no more of these three |

Every class the table does not name opens by level, so a `prov` stays closed and a `fold`, a `columns` never open. A part still renders under `openAll`.

**The focus**, which the adapter of each view names from tablo's data and the email of the person the page is seen by, `e.Page.SeenBy().Email`; "the person" below is that one:

| View | The adapter calls `e.Focus` with |
|---|---|
| `authority` | `AuthorityFocus(tasks, person)`. e2b6's rule for the filter still opens the kept path |
| `assignment` | The anchor of the person's section and of the section the `person` parameter names; and, in every section, the id of each group whose `Next` is above zero |
| `queue` | The fold of the first item on the page, when the queue is that person's own and the address names no `brief`; otherwise no id. 44bf's rule still opens the item `brief` names |
| `blockage` | `d-cause-N` of each cause whose `resolver` is the person or that holds, at any depth, a task whose `contributor` is the person, with every `h-N-ID` inside it (A6). A task that waits not yet due names no person, so no `d-next-ID` joins the focus |
| `audit` | `AuditFocus(e, groups)`: the anchor of each group whose resolver is the person. A group is one rule and one resolver (9a9c decision 3), so it holds a finding the person resolves exactly when its resolver is the person. Where the person resolves no group of the page, it names no focus, and the page arrives by level |

```go
// Holder is one task as the focus of the authority tree reads it.
type Holder struct{ ID, Parent, Assignee string }

// AuthorityFocus returns the fold ids the authority tree opens for a viewer,
// from the tasks in display order. The tops are the tasks the viewer is
// assigned that stand under no other task of the viewer's; a viewer assigned
// none takes the root. The focus holds the detail t-ID of each top, the
// children k-ID of every ancestor of a top and of each top itself, and the
// children of every parent beneath a top unless its children are all leaves
// with its own assignee. The ids stand in display order, t- before k-.
func AuthorityFocus(tasks []Holder, viewer string) []string

// Resolved is one group of the audit: the id of its fold and its resolver's email.
type Resolved struct{ Anchor, Resolver string }

// AuditFocus returns e with the audit's focus named: each group whose resolver
// is the person the page is seen by; e as it is where that person resolves none.
func AuditFocus(e Env, groups []Resolved) Env
```

On the weather station the owner `ada@example.org` gets `t-a1c0`, `k-a1c0`, `k-4e2b`; the authority `ben@example.org` gets `k-a1c0`, `t-4e2b`, `k-4e2b`; `dan@example.org`, who holds one leaf, gets `k-a1c0`, `t-3c5d`. That is `authority.html`'s sentence: the owner arrives "with the root's detail open", a parent of like leaves "folds to a count", and an authority arrives "with the subtrees they have authority over unfolded and the chain above their own tasks open".

**The audit's `minimum`.** The address carries it: `minimum=error`, `warning` or `information`, read by the audit alone, written after `stale`, absent for the default `warning`, shown in the context line, and passed to tablo as `Request.Minimum` (A11). This task carries the name from the address to the request. The control is 9a9c's, drawn by the audit's adapter, since it stands inside `<main>`: the three counts of the audit are the three links, the errors to `Page.Self("minimum", "error")`, the warnings to `warning` and the information to `information`, the current one marked with `aria-current="true"`. The counts cover every severity, so each link says what its list holds. The focus reads the groups the page lists, so a group that `minimum` hides opens nothing.

Until an adapter names a focus, `ByRole` opens exactly what `ByLevel` opens, but for `d-wider` under `Rows`. No adapter stands on `main`, so no fixture, no golden page and no existing test changes with this task.

### The rows a tableau opens on

```go
// Entry returns the rows a grid opens on when the address states no open set.
// top is the first row of the grid: the root, or the task of the task form;
// spine lists the ancestors of the person's own tasks, for the person form.
func Entry(p *Page, top string, spine []string) Unfolded

// TreeRow is one row of a grid as the open set reads it: its id and its
// parent's. A row whose parent stands in no row of the grid is a top row.
type TreeRow struct{ ID, Parent string }

// Unfold resolves the open state of the grid whose rows stand in display
// order: the open set of the address when it states one, else entry. An id
// that names no parent of the grid drops out, and so does a parent beneath a
// closed one, so that a state has one spelling. With entry.Branches the grid
// draws its first row and that row's children, whatever the address states.
func Unfold(p *Page, rows []TreeRow, entry Unfolded) *Unfolding

// Draws reports whether the grid draws the row: every ancestor of it is open.
func (u *Unfolding) Draws(id string) bool

// Open returns the open parents, sorted by id.
func (u *Unfolding) Open() []string

// Controls returns the control of a row's fold: expand, the address that
// draws the rows beneath it, or collapse, the address that folds them and
// every open row beneath; both nil for a row with no row beneath it in the grid.
func (u *Unfolding) Controls(id string) (expand, collapse *Control)

// Opened returns the address of this page with exactly the rows of ids open.
// No id is the address that states the empty set, open=.
func (p *Page) Opened(ids []string) string
```

| Page | `Entry` |
|---|---|
| `/tableau` | `{IDs: [root]}`: the root and its children, whoever reads. With `level=detail` or `level=provenance` in the address, `{All: true}`: every row, as VIEWS.md's detail states. In the export, `Branches` also |
| `/context?task=T` | `{IDs: [T]}`: the task and its children, at every level |
| `/context` and `/context?person=E` | `{IDs: spine}`: every row that stands above an own row, found by `under` (A2), so the person's tasks and their siblings show under their parents. For Ben that is `a1c0`, which tablo labels `spine`, and `4e2b`, his own task above `c07d` (886d decision 3) |

The entry never reads the viewer. A contributor "opens at the parents of their tasks" because `/` leads them to the person form of themselves, and the person form of anybody opens at that person's spine. So an address without `open` shows every reader the same rows at the same commit; on `/context` with neither task nor person, the person is the one `as_seen_by` names, else the viewer.

**The adapter calls `Unfold` once per page**, for the grid that holds the hierarchy: the tableau's `Grid`, the task form's `Grid`, the person form's `Wider.Grid`. It draws the rows `Draws` accepts and gives each `Row` the pair `Controls` returns. The person form's first grid holds the person's own tasks, every one drawn: the adapter does not call `Unfold` for it, and its rows take no control.

**The address arithmetic**, which `Controls` holds and [`cases.json`](db74/cases.json) fixes:

- The next state of an expand is the open set with the row; of a collapse, the open set without the row and without every open row beneath it.
- A next state equal to the entry state takes the address without `open`. Every other takes `Opened`, which sorts the ids; the empty set reads `open=`.
- Every other parameter of the page stays; `part` goes. `Swap` is on.
- With `Branches`, a child of the first row that has rows beneath it takes `&Control{Href: "#branch-ID"}` as expand, and no other row takes a control (44bf decision 4). On any other page without scripts no row takes a control.

`Page.Self("open", "")` removes the name, so `Self` cannot write the state "every row folded"; `Opened` exists for that (finding C1).

### The column choice

```go
// GateChoice is one gate of the project as the column choice reads it, in
// gate order: its key, whether the page shows its column, and the count of
// tasks whose current gate it is.
type GateChoice struct {
	Key   string
	Shown bool
	Count int
}

// ColumnsOf returns the column choice of a tableau page, for Grid.Control of
// its first grid, or nil in the export, which draws none.
func ColumnsOf(e Env, gates []GateChoice) *ColumnsForm
```

| Field | `ColumnsOf` sets |
|---|---|
| `Fold` | `e.Fold("columns", "columns", "", "")`: it never arrives open |
| `Action` | The route with no query: `/tableau` or `/context`. A `GET` form replaces the query, so the form restates what it keeps |
| `Hidden` | In the order of `web.Order`: `project`, `ref`, `task`, `person`, `as_seen_by`, `role`, `level`, each where the view reads it and the address states it, and `open` where the address states it, even empty. Never `columns`, `window`, `historical` or `part` |
| `Name`, `HistName` | `columns` and `historical`: the names 49ce's parser reads, repeated `columns` included (49ce, L9) |
| `Gates` | One `ColumnChoice` per gate, in gate order: the symbol from the legend, `Checked` where the page shows the column |
| `Hist`, `Shown`, `Total` | `Params.Historical`; the gates shown; every gate |
| `Reset` (new) | A `Control` with `Swap` on, to the page's address without `columns`, `window` and `part`, when the address states `columns` or `window`; nil when the page shows the default window |

`gridcolumns` in `shared/grid.html` gains one line after the button:

```
{{with .Reset}}
<a id="{{$.Fold.ID}}-reset" href="{{.Href}}" data-columns=""{{template "swap" .}}>Return to the default window</a>{{end}}
```

The link carries an id, since it is boosted (5a2f, K3). The seven fixtures hold no `Reset`, so no golden page changes. A reader hides a column by clearing its box and shows one by setting it; the form submits the whole list, which is the absolute list the address and the store hold. A submit with no box set states no `columns`, and the page shows the default window. A column outside the list folds to a count as a column outside the window does: one notation serves both (438a decision 1), and prototype db74's separate marker for a hidden column does not land. The `historical` switch travels in the address and is not stored. The stored column choice is the browser's, keyed by address and view (49ce), so it stays the viewer's own under `as_seen_by`; a person who wants their columns seen shares an address that states them.

### The script

[`db74/tableaud.js`](db74/tableaud.js) changes the `submit` listener and nothing else. On `main` every submit of `form.columns` stores the boxes set. A reader on the default window who sets "Show the marks of historical junctions" and submits therefore stores today's window as a choice, and the window stops following the project. The listener now compares each `input[name="columns"]` with its `defaultChecked`: when no box differs from what the page drew, it stores nothing (decision 7). The file has 78 lines, under the eighty of 49ce decision 4. It adds no dependency and no build step, so the README's policy on vendored assets holds as it stands. No ruling touches the script: it reads `columns` and `window` alone, moves no focus and hides no column, since the server draws each column whole (5a2f A6).

The script needs nothing else from this task. The `Reset` link carries `data-columns=""`, which the click listener on `main` reads as "clear the store". A fold link keeps the page's `columns`, since `Unfold` builds it from the page's own parameters. The level links are plain, with no `hx-boost`, so the second job of the script does not restore the folds they change (49ce, Controls).

### Two controls in the frame

```go
// Levels returns the four entries of the level control: "by role", the
// address that states no level, then the three levels. The entry the address
// states is Current. A page with no scripts or with an error has none.
func (p *Page) Levels() []NavItem

// Share returns the address that opens this page for another viewer as this
// viewer sees it: the page's own address with as_seen_by the viewer, and with
// role only when the role in force is not the viewer's first; "" where the
// address states as_seen_by already, for a viewer with no email, on a page
// with no scripts and on an error page.
func (p *Page) Share() string
```

`base.html` gains, after the context line and inside `header.site`:

```
{{- with .Levels}}
<p class="levels">Level:{{range $i, $l := .}}{{if $i}} ·{{end}} <a id="level-{{$i}}" href="{{$l.Href}}"{{if $l.Current}} aria-current="true"{{end}}><span class="sr">level </span>{{$l.Label}}</a>{{end}}</p>
{{- end}}
```

Its footer reads `… <a href="{{.Self}}">the link to this page</a>{{with .Share}} · <a id="share" href="{{.}}">the link that opens it as you see it</a>{{end}}`, and its `viewer` template gains the notice of the section above, under `{{with .AsSelf}}`. Its context line takes the class `norole` where `Unheld` holds. The sheet's joined part gains four rules and one block, in the shared block's tokens:

```
p.levels { color: var(--muted); font-size: .875rem; margin: .25rem 0 0; }
p.levels a[aria-current="true"] { color: var(--fg); font-weight: 600; text-decoration: none; }
.context strong { color: var(--fg); }
.context.norole { background: var(--mark); --muted: var(--fg); }
@media (forced-colors: active) {
  .context.norole { outline: 1px solid; }
}
```

The last two keep 5a2f's rules with no exemption: the background is a token (C2), the rule that paints `--mark` sets `--muted` to `--fg` (C3), and the forced-colours block outlines what `--mark` tints (C5). Where 5a2f's block stands, the selector joins its list.

Each new control is a native link with an id that a swap keeps, a name that reads alone ("level glance"), no `title` and no ARIA but `aria-current` (5a2f A4 and A5). The level links, the second link and "see it as yourself" are plain, with no `hx-boost`. No page on `main` offers a way to another level, though 49ce names "a `level` link" and VIEWS.md has HTML "fold and unfold" between levels: `Levels` is that link. `Share` answers the description's last sentence. `/context` shows the viewer's own corner and opens at the viewer's level, so the bare address shows its receiver another page; `Share` on Ben's corner is `/context?as_seen_by=ben@example.org`, which opens Ben's corner at Ben's level with Ben's focus for anyone. It no longer adds `person` on two views as a special case. A page whose address states `as_seen_by` already offers no second link and loses nothing: "the link to this page" already carries the `as_seen_by` the reader looks through, so it already opens as the reader sees it. A viewer with no email has no person to name, and gets none either.

### What has an address

| State | In the address | A shared link |
|---|---|---|
