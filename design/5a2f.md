# Design 5a2f: Accessibility and theming

This task makes the ten views work under a keyboard, in words where a page shows symbols, in a light and a dark theme that follow the system, and at phone width. The four template tasks already keep most of the promises [`438a`](438a.md) made to this one. The design lists what stands, adds what remains, and states every rule as a check that a test runs on every page of every fixture, as the daemon draws it and as the export draws it. Six choices shape it:

- **The floors are the numbers of WCAG 2.2 at level AA**, where a test can compute them; the design claims no conformance (decision 1).
- **A plain table and native controls.** No tree grid, no arrow keys, no `tabindex` but one, no script of this task (decision 2).
- **A state takes a second cue beside its colour**: a line under its cell, by the rank of its severity (decision 3).
- **The theme follows the system and nothing else** (decision 4), and the mockups' shared block stays byte for byte: one rule repairs the one pair that falls short (decision 5).
- **Every control but a plain link carries an id**, so that HTMX returns the focus after a swap; the script stays at two jobs (decision 6).
- **A wide tableau scrolls sideways with its task column in place.** No stacked layout, one breakpoint (decision 7).

No browser, screen reader or phone runs on the host that writes this. The document states what a test proves here and what a person tests at `validate`; it never states that a page works in a browser or a screen reader.

## The model

### The rules

The task adds these. `checkAccess` runs F1 to P1 on a rendered document and names the rule a page breaks; `TestSheetAccess` runs the rest on the sheet. [`5a2f/checks.md`](5a2f/checks.md) holds both.

| F2 | One `main#main`; one `nav`, named, outside `main`; one `header.site` and one `footer.site`, outside `main` | Landmarks |
| F3 | The first control of the body is the skip link to `#main` | S9 says it exists, not that it comes first |

| P4 | No `font-size` in pixels after the shared block; `html { font-size: 100%; }` | The reader's own font size holds, and the breakpoint follows it |
| M1 | No `transition`, `animation` or `scroll-behavior` | Nothing moves, so nothing needs `prefers-reduced-motion` |

### The keyboard

The tableau stays a plain table, as the prototype recommends (its question 2). Every action is a native control: a link, a `summary`, a checkbox, a button. Tab reaches each in the order of the page and Enter or Space works it; a reader with a screen reader keeps the table keys the reader already knows. The cost is one stop per parent row, and progressive disclosure bounds it, since only an open branch draws rows. A tree grid needs a script that moves a roving `tabindex`, which no test here can run and which a fault turns into a trap; `49ce` leaves the arrow keys to this task, and this task offers none.

**The scroller.** The grid is the one table wider than its page by design: `width: auto`, cells that never wrap, a column per gate. Its `div.scroll` becomes a stop that the caption names (K2), so the arrow keys scroll it. No other scroller becomes a stop (decision 8): under `40rem` the header cells of every other table wrap, a table that still overflows scrolls from a link or a fold inside it, and V5 tests the rest.

**The focus after a swap.** A boosted control and the server's refresh replace `#page` whole, and with it the element that holds the focus. The vendored HTMX 2.0.6 then focuses the element whose id equals that of the one it removed; the source says so, and no one has run it (A8). The ids therefore are:

| Control | Id | Template |
|---|---|---|
| A summary | Its fold's id, then `-s` | Every template; [`5a2f/summary-ids.py`](5a2f/summary-ids.py) |
| A parent's fold in a grid, "*n* rows beneath" and "fold the *n* rows beneath" alike | `<grid id>-x-<task id>` | `shared/grid.html` |
| The grid's scroller; its caption | `<grid id>-scroll`; `<grid id>-cap` | `shared/grid.html` |
| A gate's checkbox, the historical one, the button of the column choice | `<fold id>-<gate key>`, `<fold id>-historical`, `<fold id>-submit` | `shared/grid.html` |
| The two links of the authority's filter | `filter-all`, `filter-proposed` | `views/authority.html` |
| The brief | `brief-<task id>`, as it stands | `views/queue.html` |

The expander keeps one id whether it draws the rows or folds them, so the focus stays on it across its own swap. A plain link has no id: when a refresh changes the page under a reader whose focus stands on one, the focus drops to the document (V3). The design accepts that and adds no script (decision 6).

### Names

**The expander.** Its name is its visible words, then the task as hidden text: `31 rows beneath<span class="sr"> Tableaux tooling, 437e</span>`. A speaker of commands says the words on the page, and a list of links tells two parents with the same count apart (N3). The words say whether the rows stand open, so the link takes no `aria-expanded`.

**The rest stands.** A cell names its symbols in `span.sr`, a status line beside them (S6); a row says its level (S10); a fold is a `details`, which says by itself whether it is open. A refresh says nothing aloud: a live region must stand outside `#page`, which the frame does not have, and the design adds none.

### The second cue of a state

The symbols of the gates, the reasons and the marks differ in shape. Those of the states are circles that differ in colour alone, and a grid cell shows the circle with its name hidden. The cell therefore draws a line under the state: none at the lowest rank of severity, dashed at the second, heavy from the third on. The rank is data: `gates.yaml` gives every state a `severity`, and roll-up already orders by it.

```go
// SeverityRank returns the rank of the severity s among all, the severities
// of every state of one gate definition: 0 for a severity of 0, which roll-up
// sets aside; else one more than the count of distinct non-zero severities
// below s, and at most 3. A page draws a rank, never a severity.
func SeverityRank(s int, all []int) int

// WithSeverities records the severity of each state key, from the gate
// definition, and returns the legend.
func (l *Legend) WithSeverities(by map[string]int) *Legend

// Rank returns the severity rank of a state key, as SeverityRank gives it
// over the recorded severities; 0 for a key the legend lacks.
func (l *Legend) Rank(state string) int
```

`Legend` gains the field `severities map[string]int`, so `NewLegend` writes its literal with field names. Two models gain a field, after the last field each has now:

```go
// in Cell (view_status.go)
Rank int // the severity rank of the state the cell holds, 0 to 3; 0 where it holds none

// in LegendRow (view_gate.go)
Rank int // a state's severity rank, 0 to 3, as SeverityRank gives it
```

The grid writes the class `s2` or `s3` on `td.cell` where `Rank` exceeds 1, and the legend's table of states writes it on the symbol's cell, so the legend shows the cue it explains. Three fixed sentences say what the line means: one in the caption of the states, one in the key under each tableau ([`5a2f/pages.diff`](5a2f/pages.diff)). With the software gate set nominal ranks 1, at risk 2 and stalled 3; undefined and complete rank 0, and ⚪ and ✅ differ from the rest in lightness and in shape. The status adapters set `Cell.Rank` from `Legend.Rank` and the gate adapter sets `LegendRow.Rank`; until they land, the fixtures state it.

### Themes

The shared block's `prefers-color-scheme` query is the whole mechanism, and the task adds the `color-scheme` meta and rule (F1, C5). No control switches the theme: a switch needs a script and a stored choice, and the export has neither.

The arithmetic of [`5a2f/pairs.tsv`](5a2f/pairs.tsv) finds one pair short: `--muted` on `--mark` in the dark theme, 4.19 to 1, where a row a link targets, a marked cell or a proposal holds muted text. The shared block is the mockups' and `TestStyleSheetStartsWithTheSharedBlock` pins its hash, so the design changes no token. One rule sets `--muted` to `--fg` on every element that paints `--mark`; a custom property inherits, so every muted word inside reads in `--fg`, at 8.26 in the dark theme (C3). `--line` and `--prov-line` reach 1.07 to 2.91 and stay what they are, lines that separate; three edits take meaning off them: `td.hist` draws its dashed line in `--muted`, the brief's text area takes a `--muted` border, and no outline uses them (K4).

### Narrow screens

The tableau exists to compare tasks across gates, and a stack of cards per task gives that up, so the grid scrolls sideways at every width and its task column stays in place: `position: sticky` on `th.task`, which the header's own cell now carries too. Under `40rem` the task column narrows to 9rem, the depth scale steps by .5rem, the header cells of every other table wrap, and the authority's two columns stack. `pre` wraps at every width. The design holds the one breakpoint the mockups share and adds no second.

### What the design keeps and drops from prototype 5a2f

It keeps: the plain table with link expanders; names as real text and never `aria-label`; CSS alone for the themes; the contrast arithmetic as a test with its mutation; an id on each control that a swap replaces; the sideways scroll with a sticky column and a focusable scroller; the check that link text leads to one place; the parser, which `438a` moved. It drops: the tree grid and its script; a border pattern per state key, since a project names its own states and severity ranks them; the `role="status"` message, which a swap of `#page` replaces with the page; the stacked layout and the `role` attributes it needed; `prefers-reduced-motion` rules, since nothing moves; its own templates and sheet. Its seven findings: names and the list of marks stand settled (above); the second cue is decision 3, the expander's name stands under Names, the toggle is decision 4, the table is decision 2 and the breakpoint decision 7.

## Decisions at review

1. **The floor.** The design holds the pages to the numbers of WCAG 2.2 level AA where arithmetic or markup proves them: 4.5 to 1 for text, 3 to 1 for a line that carries meaning, 320 pixels of width; it claims no conformance, which needs a person's audit. The alternative is level AAA's 7 to 1, which `--muted` and `--accent` miss in the light theme and which changes the mockups' tokens. Binds `db74` (A5).
2. **A plain table.** No tree grid, no arrow keys, no script of this task; `context.html`'s comment stays as drawn. The alternative is an ARIA `treegrid` with a roving `tabindex`, which needs a third job in the script (`49ce` decision 4) and a test with a screen reader before it ships. Binds `49ce` (R5), `44bf`, `db74`.
3. **A state's second cue is a line by the rank of its severity**: none, dashed, heavy, with three sentences of fixed wording that say so.
