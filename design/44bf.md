# Design 44bf: Status templates

This task delivers the four status views as HTML: the global tableau, the contextual tableau, the work-blockage tree and the contributor work queue. All four build on the shared architecture of [`438a`](438a.md): the page, the addresses, the symbols, the folds with the lazy rule, the fold rule, the empty form and the one style sheet. This document adds the four models, their templates and what is particular to them. Four choices shape it:

- **One grid serves both tableaux.** `grid.html` draws a `Grid`: gate columns, one row per task, one cell per junction. The global tableau, both forms of the contextual tableau and each branch of an export use it unchanged.
- **A row unfolds through a link that swaps `main`.** A table has no native way to fold rows, so a parent's row carries a link to the same page with that row open; HTMX swaps `main` and pushes the address, and without script the link loads the page. The address always holds the whole open set, so no link on the page is stale. An export has no server to answer, so it draws each branch under the root whole, in a `details`, as `tableau.html` does.
- **A cell holds symbols with their names, and nothing else decides its look.** A historical cell is empty unless the parameter is on; a folded column is one column with its count in the header; the cell where the marked person acts carries `mine`.
- **The queue is one page per person with the five kinds always present**, each item a line with a lazy detail, and the brief is the provenance of one item, printed as the plain text tablo composes.

## The model

The files: `view_status.go` (the models), `adapt_tableau.go` (both tableaux), `adapt_blockage.go`, `adapt_queue.go`, and the five templates.

### The grid

| Element | Markup | Holds |
|---|---|---|
| The table | `div.scroll` around `table.tableau#<grid id>` with a `caption` | The caption says how many of the tasks in view the grid draws |
| A gate column | `th scope="col" class="gate"` | A link to the gate's legend entry: the symbol and, in `span.gname`, the key |
| A folded column | `th.gate.fold` | One column per run of folded gates: the first and the last symbol, "integrate to release" in `span.gname`, and `span.count` "folded ×*n*", read out as "*n* tasks stand here"; its cells are empty `td.cell.fold` |
| A row | `tr#<grid id>-<task id>`, `tr.parent` for a parent | The id as a link in the first cell; `th scope="row" class="task d<depth>"` with "level *n*" as `span.sr` and the title |
| A parent's fold | `a.fold` in the row header | "*n* rows beneath", a `Link` with `Swap` that draws them; "fold the *n* rows beneath" when they are drawn; a plain count where the view cannot draw them |
| A cell | `td.cell` | The symbols in one `aria-hidden` span and their names in `span.sr`; `hist` where it shows historical marks; `mine` where the marked person acts, with ", this person acts here" |
| A historical cell | `td.cell` with `span.sr` "historical" and no symbol | Empty to the eye, as the owner ruled; with the parameter on it holds the marks, the class `hist`, and ", historical" after the names |
| The status column | `td.status` with `details.detail`, when `Grid.Notes` is on | The summary is the date; the body the note, the child a roll-up comes from or the snapshot of a recursive junction, and `details.prov` with the part `row` |
| The provenance of a row | part `row`, key the task id | `dl.fields`: the status file and its deciding commit, or the chain a roll-up passes through; then per gate or run of gates with the same source the marks and the task whose entry states them; then the commands |
| The column choice | `details.columns` with `form.columns`, when the model holds `Grid.Control` | A plain `GET` form: a checkbox per gate, one for the historical junctions, a submit button. Task db74 fills `Control`; this task draws it and leaves it nil |

The state symbol sits in the cell of the gate the status names, with the reason beside it, and the cell's names read "stalled, blocked". The row header carries the depth class `d0` to `d8` (438a, finding C4).

### Which rows a tableau draws

```go
// Unfolded names the parent rows whose children a tableau draws.
type Unfolded struct {
	All      bool     // every parent
	IDs      []string // or these, in display order
	Branches bool     // draw each child of the root with its subtree as a Branch: the export
}

// DefaultUnfolded returns what a level opens on: the root at glance, every
// parent from detail on.
func DefaultUnfolded(l Level, root string) Unfolded
```

The server passes the open set of the address (`Target.Open`), or the default when the address names none; task db74 replaces the default with the role's. The adapter draws a row when every ancestor of it is unfolded. A drawn parent whose children are drawn carries `Collapse`, the address without that row and its descendants, so a collapsed state has one spelling; one whose children are not drawn carries `Expand`, the address with that row added. With `Branches` the grid draws the root and its children, each `Expand` is an anchor `#branch-<id>` with `Swap` off, and `TableauView.Branches` holds one `Branch` per child of the root that has tasks beneath it, each a `details.detail#branch-<id>` with its own grid, `grid-<id>`.

### The global tableau

`TableauView` holds the grid, the counts of rows drawn and tasks in view, and the branches. [`44bf/tableau.html`](44bf/tableau.html) draws an `h2` "*n* of *m* tasks", the grid with the status column, a `p.key` that explains a row and a cell in fixed words and links the gate definition, and the branches under an `h2` when the model holds any. With no task the grid gives way to `p.empty`.

### The contextual tableau

`ContextualView` holds either a task or a person, a grid, a `Wider` grid and one `RowBlock` per row. [`44bf/contextual.html`](44bf/contextual.html) draws:

- **The grid without the status column**: the task and its children, or the tasks the person is assigned or contributes at next. A child that is a parent shows its count of rows and no fold link when the view holds no rows for them.
- **`p.key`**: the columns by symbol and key, and which are folded.
- **`Wider`**, in the person form: `details.detail#d-wider`, "Spine, siblings and notes", with a second grid that adds the ancestors up to the root and the siblings, each sibling marked "· sibling" in its row header, and the status column.
- **One block per row**: `details.detail` whose summary is the id, the title and the status, and whose body is `dl.fields` with status, date, note and the next gate with its marks, a link to the task's definition, and `details.prov` with the part `row`.

A person with no task yields `p.empty`: "*email* is assigned no task and contributes at no next gate at this ref."

### The work-blockage tree

`BlockageView` holds the causes, largest first as tablo orders them, and the tasks with requirements not yet due. [`44bf/blockage.html`](44bf/blockage.html) draws:

| Part of the page | Markup | Holds |
|---|---|---|
| A cause | `li#cause-<n>` in `ul.tree`, `li.mine` when the marked person resolves it, with `details.detail` | The summary: the ordinal, `span.what` with the task and what holds, `span.who` with the resolver, `span.holds` with the count |
| What holds, by kind | Fixed words | requirement: "has not passed *gate*"; review: "awaits review at *gate*"; authorisation: "is proposed"; pin: "waits for its subproject at *gate*"; status: "stands *state* *reason*" |
| The action | `p` | "Action:" and the one action that resolves the cause |
| The held tasks | Nested `ul`; a held task that holds others is a `details.detail` | Each line: the task, the gate, "a parent" where it is one, and why it is held; the nesting is the transitive tree |
| The provenance | `details.prov#prov-cause-<n>`, part `facts` | `dl.fields` of labelled facts, then the command that resolves the cause |
| Next | `ul.tree` under `h2#next`, one `li#next-<id>` with `details.detail` per task | The task's status and next gate; one line per requirement that is not yet due, with its condition; `details.prov`, part `facts` |

No cause yields `p.empty` "No cause holds any task."; no requirement that is not yet due yields "Every requirement is due."

### The contributor work queue

`QueueView` holds the person, the total and always five `QueueKind` values in the order of VIEWS.md. [`44bf/queue.html`](44bf/queue.html) draws an `h2` "Queue of *email*", `p.rule` with the count of each kind, and per kind an `h3#k-<kind>` "*n*. *Title*: *count*" where an empty kind reads "none" and shows `p.empty` with a fixed sentence:

| Kind | Anchor | When empty |
|---|---|---|
| Reviews owed | `k-review` | No status carries the reason review at a junction this person reviews. |
| Authorisations owed | `k-auth` | No task is proposed in a subtree this person has authority over. |
| Work ready | `k-ready` | No next junction names this person as contributor with every due requirement met. |
| Reaffirmations | `k-reaff` | This person recorded no status. |
| Work waiting | `k-waiting` | No next junction of this person waits on a requirement or a reason. |

An item is `li#<kind>-<task id>` in `ol.items`, with the kind as its anchor names it (`review`, `auth`, `ready`, `reaff`, `waiting`): `span.q-task` with the task and, for a waiting item, its cause in `span.q-cause`; `span.q-gate`; `span.q-model` with the agent mark and the model; `span.q-since` with the date of the status, or for a reaffirmation its age. Under the line stands `details.detail`, "Detail", with the lazy part `item`: gate with its name and criteria, contributor with the model and the task whose entry supplies them, reviewer, references, requires, unblocks, status with its commit, and the command that writes the brief. Where the contributor reviews its own work the reviewer line says so and the item shows `🤖` alone (438a, decision 2).

The fold rule applies inside a kind: items are alike when gate, model and status date agree, and the fold's summary names the three. The **brief** is `details.prov` inside the detail, with the lazy part `brief`: a `label` and a read-only `textarea.brief` that holds the brief as plain text. The `brief` parameter names a task and a gate; the adapter then opens that item's detail and its brief, opens the run that holds it, and marks its line `mine`.

### Lazy parts

| View | Part | Key | Value |
|---|---|---|---|
| Both tableaux | `row` | The task id | `*RowProv` |
| Blockage | `facts` | `cause-<n>` or `next-<id>` | The `Cause` or the `Waiting` |
| Queue | `item` | The item's anchor | `*ItemBody` |
| Queue | `brief` | The item's anchor | `*Brief` |

### What the design keeps and drops from prototype 44bf

It keeps: one template for the global tableau and both contextual forms; the state at the status gate; a toggle that is a link with a full-page answer; the queue's five kinds in the data's order; "holds *n*" and one link per task. It drops: the row fragment that swaps one `tr` for several and removes rows with out-of-band deletes, whose behaviour in a table no one has run, in favour of the swap of `main` that prototype db74 uses; with it the prototype's finding of stale links after a swap; the blanking of historical cells in the template, which tablo's data now states (A3); the stand-in brief; the fold column's range `from..to` in words, which the two symbols and the names replace; the `title` attributes.

Where a page departs from its mockup:

- **Narration and illustration.** No page renders the mockup's explaining paragraphs, the "Variations" of `tableau.html` (each is the same page under another parameter), the table of the five kinds of cause that `blockage.html` shows for an empty tree, or the illustrative trees and items of `blockage.html` and `queue.html`.
- **One form for a cell.** `tableau.html` wraps a cell's symbols in `aria-hidden` and names them "agent, reviewer"; `context.html` leaves the symbols bare and names them "an agent contributes; a reviewer accepts", with `title` attributes on the column headers. The grid uses `tableau.html`'s markup and the method's phrases (438a, decision 3).
- **One form for a fold.** The count stands in the header (438a, decision 1); `context.html`'s first-row count and its narrow table of folded counts go.
- **The notes of the person form** stand in the status column of the wider grid, as in the global tableau, not under each title as `context.html` has them (decision 3).
- **The global tableau's parameters** stand in the context line, not in `dl.params`; the column choice is `context.html`'s form in `tableau.html`'s `details.columns` (438a, findings C3 and C13).
- **One queue per page.** `queue.html` sets two people's queues on one page; the page serves one person.
- **An empty kind** shows a fixed sentence in `p.empty`, where `queue.html` composes one from the person's positions inside a `details`.

## Decisions at review

The owner decided each question this design raised on 2026-10-06, together with the cross-design rulings of that review; a decision the review did not reach stands as the design states it, accepted with the design.

1. **How a row unfolds.** Accepted with the design, as stated: a link that swaps `main` and pushes the address, with the whole open set in every link. The alternative is prototype 44bf's row fragment, which sends less per click and leaves the other rows' links stale until a reload.
2. **The brief's text.** Accepted with the design, as stated: tablo composes it and both front ends print it (A11); tabloio's e4c7 decision 2 asks the same of tablo. The alternative lets each front end compose the brief from its six parts, and two briefs for one item may then differ. Binds tablo's `886d` and tabloio's `e4c7`.
3. **Notes in the person form.** Accepted with the design, as stated: in the status column, as in the global tableau. The alternative is `context.html`'s `span.note` under each title, a second form of the same fact.
4. **The export's form of the tableau.** Accepted with the design, as stated: a branch per child of the root in a `details`, as `tableau.html` draws it, under `Unfolded.Branches`. The alternative draws one grid with every row, with no fold at all in an export. Binds 6160.
5. **The provenance of a cause.** Accepted with the design, as stated: labelled facts as tablo states them (A9). The alternative types each fact here and fixes the labels in the template.
6. **The shared rulings.** Decided by the owner on 2026-10-06, through 438a: the fold count in the column header, parents included by their roll-up (438a decision 1); the self-review mark in its general form (438a decision 2); a long list folds from more than eight alike rows (438a decision 5); the number after a folded parent counts every row beneath it, as `tableau.md` reads it (679b decision 8); and an absent `person` is the viewer on the queue and on the contextual tableau without a task, and nobody on the global tableau and the blockage tree (5ca9 decision 3). The brief's command, where a page prints it, writes `--person` and `--ref`.
7. **The reconciliation with the server as built.** Decided by the owner on 2026-10-07, as proposed, with each of the nine questions of the mapping answered by the choice it makes: [`438a/server.md`](438a/server.md) maps the four template tasks onto the Server as `main` holds it.
