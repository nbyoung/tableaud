# Design 49ce: Server

`tableaud serve` runs in a checked-out repository and answers one route per view. This design fixes the frame every other tableaud task fills: the command line, the routes and one URL scheme, who the viewer is, the contract between the server and a view's template, the assets, the error pages, the reload when the repository changes, and the limits the daemon keeps. Five choices shape it:

- **A link is a value, and a `Linker` spells it.** A template never writes an address. The daemon spells a link as a path and a query; the static export spells the same link as a file path (A8). That is how one scheme holds where no server answers a query string.
- **The routes and the query names take the mockups' words**: `/gates`, `/context`, `person`, `ref`, the names the mockups' own commands use (D1, D2).
- **Every page is live.** One digest of the repository keys every page, an open page polls its own address with its tag, and the daemon answers `304` until the digest changes.
- **One script of tableaud's own, under eighty lines, beside HTMX**: it keeps a viewer's columns in the browser and keeps open folds across a reload. No JavaScript toolchain follows from it (D4).
- **The server computes no level and holds no column policy.** It validates, loads and frames; the templates open and fold.

## The model

### Packages

| Path                  | Holds                                                                                              |
|-----------------------|----------------------------------------------------------------------------------------------------|
| `cmd/tableaud/`       | `main.go` dispatches `version` and `serve`; `serve.go` parses the options, wires the three packages, listens and shuts down |
| `internal/source/`    | `Source`, the one seam to tablo; `tablo.go`, the adapter (A1 to A7); `sourcetest/`, a `Source` over JSON fixtures for every test |
| `internal/web/`       | What a page is, for the daemon and the export alike: `View`, `Params`, `Link`, `Linker`, `Page`, `Render`; `templates/`; `static/` |
| `internal/serve/`     | The HTTP side: `Server`, the query parser and writer, the daemon's `Linker`, the watcher, the cache |

`web` imports `source`; `serve` imports both; nothing imports `serve` but the command. The export (`6160`) imports `web` and `source` and never `serve`.

### Command line

```
tableaud serve [-C DIR] [--addr HOST:PORT] [--as EMAIL] [--ref REF]
               [--poll DURATION] [--allow-host NAME[,NAME…]]
```

| Option         | Default                                  | Meaning                                                                                   |
|----------------|------------------------------------------|-------------------------------------------------------------------------------------------|
| `-C`           | `.`                                      | The directory that holds `.tableaux`; its repository is the nearest ancestor with `.git`   |
| `--addr`       | `127.0.0.1:8642`                         | The one address the daemon binds. Port `0` takes a free port                                |
| `--as`         | `git -C DIR config --get user.email`     | The viewer for a loopback peer (see [Viewer and role](#viewer-and-role))                    |
| `--ref`        | none: the working tree on `HEAD`         | The ref a page reads when its address states none                                           |
| `--poll`       | `2s`                                     | How often an open page asks whether it changed; `0` turns the poll off; otherwise at least `250ms` |
| `--allow-host` | none                                     | `Host` names to accept beside the loopback names                                            |

`tableaud serve` requires the word `serve`; `tableaud` alone prints the usage and exits 2. A long name behind one hyphen (`-addr`) exits 2 and names the `--` form, as the prototype does. The command prints one line to standard output once it listens, `tableaud: serving http://127.0.0.1:8642/ from DIR as EMAIL`, and, when the bound address is not loopback, one warning to standard error that names `--allow-host`. It logs each `5xx` to standard error and nothing else.

| Exit | When                                                                                      |
|------|-------------------------------------------------------------------------------------------|
| 0    | A signal stopped the daemon and it shut down                                              |
| 1    | The daemon cannot listen, or the listener fails                                           |
| 2    | A usage error                                                                             |
| 3    | The daemon cannot read: no repository at or above `DIR`, no `.tableaux` in `DIR`, an unknown `--ref` |

A project that does not validate is no exit: the daemon starts, its pages say so (see [Errors as pages](#errors-as-pages)), and they heal when the files do.

### Routes and the URL scheme

`GET` and `HEAD` alone; any other method answers `405` with `Allow`. The routes are `/`, `/static/…` and one per view, in the order of the mockups' nav:

| Route         | View (VIEWS.md)         | Nav label   | Reads, beside the shared names                                   |
|---------------|-------------------------|-------------|------------------------------------------------------------------|
| `/tableau`    | Global tableau          | Tableau     | `person`, `window` or `columns`, `historical`, `open`            |
| `/context`    | Contextual tableau      | My corner   | `task` or `person`, `window` or `columns`, `historical`, `open`  |
| `/queue`      | Contributor work queue  | Queue       | `person`, `task`, `brief`                                        |
| `/blockage`   | Work-blockage tree      | Blockage    | `task`, `person`                                                 |
| `/task`       | Task definition         | Task        | `task`, `person`                                                 |
| `/assignment` | Task assignment         | Assignment  | `person`, `task`                                                 |
| `/authority`  | Authority delegation    | Authority   | `task`, `person`, `proposed`                                     |
| `/history`    | History                 | History     | `task`, `person`; `ref` may be a range                           |
| `/audit`      | Audit                   | Audit       | `task`, `person`, `stale`                                        |
| `/gates`      | Gate definition         | Gates       | `task`                                                           |

Every view reads the five shared names `project`, `ref`, `role`, `level` and `part`. The query names, in the order the canonical address writes them:

| Name         | Value                                                                                         | Absent means                          |
|--------------|-----------------------------------------------------------------------------------------------|---------------------------------------|
| `project`    | The `url` of a recursive junction or a cross-project requirement of the project served, at most 200 characters, no leading hyphen, no control character | The project served |
| `ref`        | A ref from the prototype's character set (`[A-Za-z0-9._/@+-]`, no leading hyphen, no `.lock`, no `//`); on `/history` also `FROM..TO` with exactly one `..` | `--ref`, else the working tree on `HEAD` |
| `task`       | Four lowercase hexadecimal digits                                                              | The root                              |
| `person`     | One email address, at most 254 characters                                                      | The view's own default (A4, D7)       |
| `role`       | `owner`, `authority`, `assignee`, `contributor`, `agent`, `reviewer` or `observer`              | The viewer's role at each item        |
| `level`      | `glance`, `detail` or `provenance`                                                             | The role's level                      |
| `window`     | A whole number from 0 to 50                                                                    | A window of one; `window=1` drops out |
| `columns`    | Gate keys (`[a-z][a-z0-9_-]{0,31}`), comma-separated or as repeated names, at most 32; an empty value counts as absent | The window |
| `historical` | `on`                                                                                           | Off                                   |
| `open`       | Task ids, comma-separated or repeated; the canonical form sorts them and drops repeats; `open=` with no value is the empty set | The role's rows (A10) |
| `proposed`   | `on`                                                                                           | Every task                            |
| `stale`      | A whole number of days from 1 to 36500                                                         | Seven; `stale=7` drops out            |
| `brief`      | `TASK:GATE`                                                                                    | No item named                         |
| `part`       | A name in the view's `Parts`                                                                   | The whole view                        |

The rules, each with cases in [`cases.json`](49ce/cases.json):

- **Validation precedes everything.** A name outside the table, a malformed value, a name given twice (`columns` and `open` excepted), `window` with `columns`, `task` with `person` on `/context`, a range off `/history`, or a `part` the view does not list answers `400`. A well-formed ref, task, project or gate the repository lacks answers `404`, which tablo decides (A6). An email in no position is no error: the view is empty (A4).
- **A parameter a view does not name has no effect**, as VIEWS.md says: the parser accepts it and the canonical address drops it.
- **The canonical address** is the route, then the parameters the view reads whose value differs from the default, in the table's order, with `@`, `,`, `/` and `:` unescaped. The page's own link, its live poll and every link a `Page` method returns are canonical. The daemon does not redirect a request to its canonical form.
- **Three redirects**, each `303` with `Cache-Control: no-store`. `/` leads to the viewer's landing page. `/task` with no `task` leads to `/task?task=ROOT`, so the nav's Task entry leads somewhere and every task page names its task (D10). `/context` with neither `task` nor `person`, for a viewer with no email, leads to `/tableau`: an observer has no corner.
- **Sticky parameters.** A link from one page to another carries the page's `project`, `ref` and `role`; a range carries as its `TO`. Nothing else travels: `person` and `task` belong to the link that states them. On a page that has a `project`, a link that names a further `project` has no address: `To` returns the empty string and the template draws text (D11).
- **Anchors of the legend** are part of the scheme: `gate-KEY`, `state-KEY`, `reason-KEY`, and `mark-person`, `mark-agent`, `mark-reviewer`, `mark-subproject`, `mark-exempt`, as `gates.html` has them.
- **No other route.** An email and a commit are text, as in every mockup; the scheme has no `/person/…` and no `/commit/…`, which prototype `438a` assumed.

### Viewer and role

The daemon takes the viewer from the connection, not from the address, since an address travels and the viewer does not:

- A request from a loopback peer is the person at the machine: the viewer is `--as`, else the repository's `user.email`, read once at start.
- A request from any other peer is an observer, with no email. A daemon that someone binds to another interface therefore never lends its owner's identity to a visitor (D6).
- A viewer with no email, or with an email in no position, is an observer.

tablo names the roles the viewer holds in the project (A5). `/` leads the owner to `/tableau`, any other viewer with a role to `/context`, which opens on the viewer's person form, and an observer to `/tableau`, as `tableau.html` states. The frame's context line reads "viewer EMAIL, ROLE" with the first role tablo names, or "viewer: an observer".

The server opens and folds nothing. A template reads `Page.Viewer`, `Params.Role` and `Params.Level` and decides which `<details>` carry `open`, as its mockup states for each role; `level` overrides, and `role` reads the page as that role. Progressive disclosure (`db74`) refines the entry states inside the two tableaux.

### The handler contract

A template task fills in one file, `internal/web/templates/views/NAME.html`, and one field, `Parts`, of its entry in `web.Views`. The file defines `view`, the content of `<main>`; `context`, what the view adds to the frame's context line; and one `part/PART` per part. `Render` clones the frame for each view, so the names do not collide. Files under `templates/shared/` parse into every view. This task lands ten placeholder files that print the view's title and its data as indented JSON, so the daemon answers every route before a template task lands.

```go
package web

// View is one of the ten views: a route, a nav entry and a template file.
type View struct {
	Name   string   // the route /Name, templates/views/Name.html, the class of <main>
	Title  string   // "Global tableau"
	Label  string   // the nav entry: "Tableau"
	Params []string // the query names the view reads beside the five shared ones
	Parts  []string // the fragments a template task serves; empty in this task
}

// Views lists the ten views in the order of the mockups' nav.
var Views []View

// Params is one validated request to a view. serve.ParseQuery builds it;
// Window is -1 and Stale is 7 when the address states neither.
type Params struct {
	Project, Ref, Task, Person, Role, Level string
	Window, Stale                           int
	Columns, Open                           []string
	OpenSet                                 bool   // open= is present, even empty
	Historical, Proposed                    bool
	Brief                                   string // TASK:GATE
	Part                                    string
}

// Link names a page: a view and its parameters.
type Link struct {
	View   string
	Params Params
}

// Linker spells an address. The daemon's writes a path and a canonical query;
// the export's writes a relative file path (A8).
type Linker interface {
	Page(l Link) string        // a view page, or one part when l.Params.Part is set
	Static(name string) string // "tableaud.css", "htmx/htmx.min.js"
}

// Page is everything a template receives.
type Page struct {
	View    View
	Params  Params
	Project *source.Project // nil only when the project did not load
	Viewer  source.Viewer
	Data    any        // tablo's data for View at Params, every level in it (A3)
	Legend  any        // tablo's gate definition at the same revision (A3)
	Link    Linker
	Live    *Live      // the poll's URL, Every and Headers; nil when --poll is 0 and on the export
	Scripts bool       // false on the export
	Err     *PageError // Status, Text, Message, Diagnostics, Reset; Data is then nil
	Version string     // the tableaud version, for the footer
}

// To returns the address of another view: the sticky parameters of p, then
// the name and value pairs given, as in To("task", "task", "9f31").
func (p *Page) To(view string, pairs ...string) string

// Self returns the address of this page with the pairs set. An empty value
// removes a name, and setting window or columns removes the other.
func (p *Page) Self(pairs ...string) string

// Anchor returns the address of a legend entry, as in Anchor("gate", "design").
func (p *Page) Anchor(kind, key string) string

// Reference returns the address of a task reference or of a text of the
// method, and false when the daemon gives it no link (D9).
func (p *Page) Reference(url string) (string, bool)

// Render writes one body: the Document, the Fragment <div id="page">, or one
// Part. It executes into a buffer first, so a template error becomes a 500
// page and never half a page.
func Render(w io.Writer, shape Shape, p *Page) error
```

The small types follow the frame: `Shape` is `Document`, `Fragment` or `Part`; `Live` holds `URL`, `Every` and `Headers`; `PageError` holds `Status`, `Text`, `Message`, `Reset` and `Diagnostics`; `Page.Nav` returns ten `NavItem` values of `Href`, `Label` and `Current`, and `Page.Title` the `<title>`, "VIEW · PROJECT". `web.Funcs` is the templates' function map; this task puts `json` in it, for the placeholders, and a template task adds its own.

**The three shapes of one route.** A request with `HX-Request: true` and without `HX-History-Restore-Request` receives a fragment; every other request receives the document. With `part=PART` the fragment is that part alone; without `HX-Request` the same address answers the whole document, in which the template draws that part open, so a link in a fold's body works with script off. Every response carries `Vary: HX-Request, HX-History-Restore-Request`.

**What a template must not do**, so that the export renders the same file (prototype `6160`, question 3): write or assemble an address; branch on the medium or a header; read the clock; load a script. `TestTemplatesStayNeutral` (T19) scans for the literal forms.

```go
package source

// Request asks tablo for one view.
type Request struct {
	View                 string    // a name in web.Views
	Project, Ref         string    // Ref empty: the working tree on HEAD (A2)
	Task, Person, Viewer string
	Window, Stale        int
	Columns              []string
	Historical, Proposed bool
	BriefTask, BriefGate string
	Today                time.Time // the audit's clock (A7)
}

// Result is tablo's answer. The server never looks inside Data.
type Result struct {
	Data    any
	Project Project
	Viewer  Viewer
}

// Project is what the frame says of the project in view.
type Project struct {
	Title, Root string // the root task's title and id
	Ref, Commit string // the ref as named, or HEAD's branch; the commit it stands at
	Date        string // that commit's author date, YYYY-MM-DD
	Worktree    bool   // the files come from the working tree
}

// Viewer is the viewer and the roles tablo finds for the email, owner first.
type Viewer struct {
	Email string
	Roles []string
}

// Source is everything the daemon and the export ask of tablo. An
// implementation is safe for concurrent use. View returns ErrNotFound,
// wrapped with the thing missing, or *InvalidError with tablo's diagnostics
// when the project does not load. Describe answers with no view, for "/".
type Source interface {
	View(ctx context.Context, r Request) (Result, error)
	Describe(ctx context.Context, project, ref, viewer string) (Project, Viewer, error)
}
```

`Short` on `Project` gives seven digits of the commit and `Role` on `Viewer` the first role or `observer`; a `Diagnostic` holds `Severity`, `Code`, `Path` and `Message`. `open`, `role`, `level` and `part` never reach tablo: they choose what a template draws, not what tablo derives.

### Controls: a link, an HTMX request or the script

`PLAN.md` leaves to the mockups whether the daemon needs script beyond HTMX. The mockups draw seven controls at rest and describe their behaviour; the server offers each as follows.

| Mockup and its words                                                                             | The server offers                                                                                   |
|--------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------|
| `tableau.html`: "redraws the grid when the viewer hides or shows a column, keeps the choice in the browser and carries it in the link" | Each button becomes `<a href="{{.Self "columns" LIST}}" data-columns="LIST" hx-boost="true">`; the default-window control is the same with an empty list. The script stores the list |
| `context.html`: the columns form; "keeping the choice for the next visit … needs script"          | The form as drawn, with `class="columns"` and `hx-boost="true"`. The script stores what it submits   |
| `tableau.html`: "unfolds each parent in place, one level at a time, and its link carries the open rows" | A link with `hx-boost="true"` to `{{.Self "open" IDS}}`. No script                              |
| `context.html`: "with script, the daemon moves those rows into the table above, … a tree grid with arrow keys" | The same `open` link, and the template draws the open rows in the table. Arrow keys stay with Accessibility (`5a2f`); the server offers none |
| `authority.html`: "the filter in its resting state: two plain links, no script"                   | Two plain links: `{{.Self "proposed" ""}}` and `{{.Self "proposed" "on"}}`                           |
| `assignment.html`: "the person and task parameters are links"; `queue.html`: "each person's queue as a page of its own" | Plain links: `{{.To "assignment" "person" EMAIL}}`, `{{.To "queue" "person" EMAIL}}` |
| Every page: a `<details>` per level                                                               | Native `<details>`. A heavy fold fetches its body as a part: `hx-get="{{.Self "part" PART}}" hx-trigger="toggle once" hx-target="find .fold-body"`, with a plain link to the same address in the body (prototype `438a`) |

**One rule for a control that changes the page's state.** It is a link, or a `GET` form, to the address of the new state, with `hx-boost="true"`. The frame's `<div id="page">` carries `hx-target="this"` and `hx-swap="outerHTML"`, so HTMX swaps the page fragment in and pushes the address, and with script off the browser follows the link. A control that changes which folds stand open, such as a `level` link, is a plain link with no boost, so that the script's second job does not undo it.

**The script**, [`tableaud.js`](49ce/tableaud.js), loads in `<head>` after HTMX and has two jobs:

1. **Columns.** On a click on `a[data-columns]` or a submit of `form.columns` it stores the list under `tableaud.columns.tableau` or `tableaud.columns.context` in `localStorage`; the empty list removes the entry. On the load of `/tableau` or `/context` with neither `columns` nor `window` in the address, it replaces the address with the same one plus the stored `columns`. An address that states either wins and stores nothing, so opening a shared link is reading, not deciding. The server sees the choice only as `columns` in an address and keeps none: no cookie, no session.
2. **Folds.** Around every swap of `#page` it notes which `<details>` with an `id` stand open and restores them, so a reload leaves the viewer's folds as they were. A fold fetched as a part fetches again when the script reopens it.

The stored list is absolute, as `PLAN.md` asks of a link, so it replaces the computed window until the viewer returns to the default (D5). A stored gate the project no longer has yields the `404` page, whose one control returns to the default window and clears the store.

### Static assets

`/static/NAME` serves the files `internal/web/embed.go` embeds, each with an `ETag` of its SHA-256, computed at start, and `Cache-Control: no-cache`, so a new binary's assets replace the old at the next request. A directory answers `404`; the daemon lists nothing.

| File                         | Content                                                                                               |
|------------------------------|-------------------------------------------------------------------------------------------------------|
| `static/htmx/htmx.min.js`    | HTMX 2.0.6, vendored already, with its `LICENSE`                                                       |
| `static/tableaud.js`         | The script                                                                                            |
| `static/tableaud.css`        | The one style sheet. It starts with the mockups' shared block, the bytes from `/* shared:` to `/* end shared */` that all ten carry (SHA-256 `7289aef0…d17d5fe`, T20). Each template task appends its view's rules after it, under `main.NAME`, the class the frame gives `<main>` (D8) |

Every response carries `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin` and `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`. The mockups set `style="--d:1"` on rows, hence `'unsafe-inline'` for styles; the frame's `htmx-config` sets `allowEval` to false to match `script-src`.

### Errors as pages

An error is a page in the frame, as a document or a fragment by the request's shape, with the nav, so the reader goes on from it.

| Status | When                                                               | The page                                                              |
|--------|--------------------------------------------------------------------|-----------------------------------------------------------------------|
| 400    | A parameter fails validation                                       | The reason, naming the parameter; no poll                             |
| 403    | The `Host` is neither a loopback name nor allowed                  | Plain text `forbidden host`: no frame, nothing of the project         |
| 404    | No such route; or tablo lacks the ref, task, project or gate       | What is missing; it polls, since a commit can supply it               |
| 405    | A method other than `GET` and `HEAD`                               | Plain text, with `Allow`                                              |
| 500    | A template fails, or tablo fails otherwise; logged                  | The message; it polls                                                 |
| 503    | The project does not load or validate (`*source.InvalidError`), or tablo exceeds 30 seconds | tablo's diagnostics, each with code, severity, path and message; it polls, so the page heals when the files do |

The frame's `htmx-config` maps every status but `204` and `304` to a swap, so a poll that meets an error draws it and a poll that meets the healed page draws that.

### Caching and reload

**The digest.** `serve.Watcher` reduces everything a page depends on that changes without a request to one string: the bytes of `HEAD`; the name, size and modification time of every file under `refs/`, of `packed-refs` and of every file under `reftable/`, in the worktree's own Git directory and in the common one; of `.gitmodules` and of each `modules/*/HEAD`; and of every entry under `DIR/.tableaux`. Names hash relative to their root. It starts no process and no goroutine: `Current()` rereads when its last read is older than 100 ms. A failure to read is a digest too, `error: MESSAGE`, so a broken repository is a change and heals as one.

The digest resolves no ref, which drops the prototype's `packed-refs` parser. Any ref that moves changes it: the trunk, which authorisation reads whatever the ref (VIEWS.md), a tag, a fetch. So no page is immutable, the prototype's pinned mode goes, and one rule serves every page. A change that leaves a page's content as it was costs one render.

**The tag.** `ETag` is 16 hexadecimal digits of the SHA-256 of the view, the canonical query, the digest, the shape, the viewer's email, `--ref`, the tableaud version and, on `/audit` alone, today's date (A7). A view response carries it with `Cache-Control: private, no-cache`. A request whose `If-None-Match` holds the tag, in a list, with `W/` or as `*`, answers `304` before any call to tablo. The tag derives from the key and never from the body, so a poll costs one `Current()`.

**The poll.** The frame's `<div id="page">` carries `hx-get` with the canonical address, `hx-trigger="every 2s"` and `hx-headers` with `If-None-Match` set to the fragment's tag. Unchanged, the daemon answers `304` and HTMX swaps nothing; changed, it answers the new fragment, which carries its own tag, and the script keeps the folds (D12). `historyCacheSize` is 0, so HTMX keeps no copy of a page in the browser's storage.

**The data cache.** The server keeps the last 64 `Result` values by digest and `Request`, oldest out first, so the parts and the levels of one page cost tablo one call. It caches no error.

**What the daemon needs of a watcher.** A cheap, comparable value on request; no process per request, which rules out the `git rev-parse` poll that suits `tablotui`'s once a second (prototype `171b`); bounded staleness; coverage of `HEAD`, every ref, a linked worktree and the working tree's `.tableaux`; and no event, since a page asks. This design shares no watcher with `171b`: the two differ in who asks and how often. If tablo later exports a repository digest, `watch.go` becomes one call to it.

Limits: an edit that keeps a file's size and its modification time to the file system's resolution passes unseen until the next change; a subproject named by an absolute URL and read through tablo's cache is not watched.

### Shutdown, and what the daemon never does

`SIGINT` or `SIGTERM` stops the listener, lets requests in flight finish for at most five seconds, then closes and exits 0. The HTTP server sets `ReadHeaderTimeout` to 10 seconds, and each view request runs under a 30-second context.

The daemon never:

- writes to the repository: it opens no file there for writing, runs one `git` command, `config --get user.email`, and takes no lock;
- binds an address other than `--addr`, whose default is loopback;
- answers a `Host` it does not know, on any path, which stops DNS rebinding (prototype, question 5); the check is no authentication;
- accepts a request that changes anything: no `POST`, no form but `GET`;
- sets a cookie, keeps a session, or stores a viewer's choice;
- opens a connection of its own: no fetch, no CDN, no telemetry;
- serves a file of the repository: every byte it sends comes from tablo's data or from the binary.

### Kept from the prototype, and dropped

Kept: one route per view; the `Source` seam; validation before the conditional check; the tag from the key; the poll of the page's own address with an explicit `If-None-Match`, and the `htmx-config` that stops a `304` from swapping; the `Host` check with its nineteen cases; the working tree as the default; the hyphen rule; the ref's character set.

Dropped: `as` and `at` for `person` and `ref`; `/gate` and `/contextual`; the pinned, immutable mode; the `packed-refs` parser and the resolved commit in the key; `window` and `columns` on the views that list; `true` and `false`; plain-text errors; `--render`, `--fragment`, `--measure` and `--labels`, which served the prototype's questions. `prototype/49ce/` stays as the record; the implementation copies `params.go`'s checks and the `Host` test table and rewrites the rest.
