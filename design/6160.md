# Design 6160: Static export

`tableaud export --out <dir>` writes the views of one project at one commit as a directory of HTML files that any static host serves and that a file system opens, with no daemon, no script and no request outside the directory. Four choices shape it. The bundle is **flat**: every page sits in one directory under a name that carries its focus, `task-9f31.html`, so a link is a bare file name and needs no base path. The export **renders through the Server's own entry** with a linker of its own, so the daemon and the bundle share every template. It freezes **the observer's arrival**: no viewer, every level in the page behind native `details`, each closed. And it **checks its own bundle before it writes a byte**: a script, a form, an absolute address or a link that names no file fails the export instead of reaching a host.

## The model

### The command

```
tableaud [-C <dir>] export --out <dir> [--ref <ref>]
```

| Option        | Default  | Meaning                                                                                                   |
|---------------|----------|-----------------------------------------------------------------------------------------------------------|
| `-C <dir>`    | `.`      | The directory that holds `.tableaux`; the command runs as if started there, as `git -C` does (A1)          |
| `--out <dir>` | required | The output directory, resolved after `-C`. It is absent or empty; its parent exists                       |
| `--ref <ref>`  | `HEAD`   | The commit to export, any name Git resolves to a commit. A range is a usage error                         |

The export takes no other option: no person, no role, no level, no window. It reads a commit and never the working tree, so an uncommitted edit under `.tableaux` does not appear. A long option behind one hyphen is a usage error that names the two-hyphen form, as in every prototype.

On success the command prints one line to standard output and nothing else:

```
wrote 32 files, 612345 bytes to public at main edb30d2, 2026-09-28
```

| Exit | When                                                                                                                                             |
|------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| 0    | The bundle stands in the output directory                                                                                                        |
| 1    | The export refuses: the output directory holds something, two people need one file name, or the bundle check finds something. The export writes nothing |
| 2    | A usage error; usage on standard error                                                                                                           |
| 3    | A failure to read (no project, an unknown ref, a view the source cannot give) or to write                                                        |

Every message goes to standard error as `tableaud: export: <what>`; a check finding reads `tableaud: export: <file>: <rule>: <detail>`, one line each, sorted.

### What the bundle holds

The bundle holds one project, the one at `-C`, at one commit, for a reader with no email. Each view gets one **landing file** under the stem of its mockup; the three views that vary by task or person get one file per focus beside it. With *T* tasks, *C* tasks that have children (the root always counts) and *P* people:

| View                   | Landing file      | Holds                                               | Files per focus                                                              | Count       |
|------------------------|-------------------|-----------------------------------------------------|------------------------------------------------------------------------------|-------------|
| Global tableau         | `index.html`      | The view: default window, historical junctions off  | none                                                                         | 1           |
| Gate definition        | `gates.html`      | The view, no task                                   | none                                                                         | 1           |
| Task definition        | `task.html`       | A list of every task                                | `task-<id>.html`, every task                                                 | 1 + *T*     |
| Authority delegation   | `authority.html`  | The view over the whole tree                        | none                                                                         | 1           |
| Task assignment        | `assignment.html` | The view, every email                               | none                                                                         | 1           |
| Contributor work queue | `queue.html`      | A list of every person                              | `queue-<person>.html`, every person                                          | 1 + *P*     |
| Work-blockage tree     | `blockage.html`   | The view over the root, every person                | none                                                                         | 1           |
| Contextual tableau     | `context.html`    | A list of every person and of every task with children | `context-<id>.html`, each task with children; `context-<person>.html`, every person | 1 + *C* + *P* |

Beside them stand `manifest.json` and, under `static/`, each asset a page asks for. The total is 10 + 2*T* + *C* + 2*P* files without assets.

**The people** are the emails the project names in a position: the rows of the task assignment view at glance (A7). **The tasks** are the tasks of the project at the commit. A task of a subproject gets no page (D2).

**The three lists.** A queue belongs to one person, a corner to one person or one task, a task page to one task, and a bundle has no viewer to take the default from. So `task.html`, `queue.html` and `context.html` are pages the export draws itself from [`choose.html`](6160/choose.html), inside the chrome every view shares (A5). They also make every file reachable whatever the view templates link: `task.html` links each task's page, its history and its corner, and `queue.html` and `context.html` link each person's two pages.

**Everything else is fixed at its default.** The bundle varies no page by window, columns, historical junctions, range, stale age, role, level, brief or the proposed filter, nor by person on a view that only marks or filters by one. A link that carries one of these lands on the page without it.

### The file names and the links

Every page sits at the bundle root, so every link is a file name with an optional fragment, and it resolves the same from `file:`, from a host's root and from any path prefix. The names carry values, never a parameter's name, so the bundle does not depend on how the daemon spells its queries.

A template never writes an address: it asks the linker (A3). In the export the linker answers with the rules below, where a **known** task or person is one in the project's index. [`6160/paths.tsv`](6160/paths.tsv) holds cases for rules 1 to 7.

1. A target in another project, or one that names an unknown task or person, has **no page**: the linker says so and the template writes the text without a link.
2. `tableau`, `gates`, `authority`, `assignment`, `blockage` and `audit` map to their landing file, whatever else the target carries.
3. `task`: `task-<id>.html` with a task, `task.html` without.
4. `queue`: `queue-<person>.html` with a person, `queue.html` without.
5. `history`: `history-<id>.html` with a task that is not the root, `history.html` otherwise.
6. `context`: with a task, `context-<id>.html` of the nearest task with children, itself included; else with a person, `context-<person>.html`; else `context.html`.
7. A fragment follows unchanged after `#`. The export invents none.
8. An asset maps to `static/<name>`, and the export then copies that asset into the bundle.
9. A reference, a `url` from a task file or the address of one of the method's texts, has no address in the bundle, relative or absolute: the template writes it as text (D6).

The addresses prototype 49ce serves become, for `weather-station`:

| The daemon answers                                 | The bundle holds                                   |
|----------------------------------------------------|----------------------------------------------------|
| `/`, `/tableau`, `/tableau?columns=defined,design` | `index.html`                                       |
| `/task?task=9f31`                                  | `task-9f31.html`                                   |
| `/task`, which the daemon refuses with 400         | `task.html`, the list                              |
| `/queue?as=ben@example.org`                        | `queue-ben@example.org.html`                       |
| `/contextual?task=4e2b`, `/contextual?task=9f31`   | `context-4e2b.html`                                |
| `/contextual?as=ben@example.org`                   | `context-ben@example.org.html`                     |
| `/history?task=9f31`, `/history?at=W1..main`       | `history-9f31.html`, `history.html`                |
| `/gate#gate-design`                                | `gates.html#gate-design`                           |
| `/task?task=8608&project=subprojects/tableaud`     | no file; the id as text                            |

**A person in a file name.** The name keeps each byte of the email in `A-Z a-z 0-9 . _ @ + -` and writes every other byte as `~` and two lower-case hexadecimal digits: `o'neil@x.org` gives `o~27neil@x.org`. The mapping is one to one, the result needs no escaping in a link, holds none of the characters Windows forbids in a file name, and holds no colon, which would turn the link into a scheme. Two people whose names agree when lower-cased would share a file on a file system that ignores case, and a name over 255 bytes fits none: the export refuses both with exit 1 and names the emails.

### What the bundle states about its source

Every page states the source in the line under the navigation, as the mockups draw it: the ref as given to `--ref`, the abbreviated commit and the commit's author date, with no viewer (A6). `manifest.json` states it in full:

```json
{
  "schema": "tableaud-export/1",
  "generator": { "tableaud": "0.1.0", "tablo": "0.1.0" },
  "ref": { "name": "main", "commit": "edb30d2baa5ea3c7e3fb8eef8ac6cce6e145221a", "date": "2026-09-28T12:00:00Z" },
  "trunk": { "name": "main", "commit": "edb30d2baa5ea3c7e3fb8eef8ac6cce6e145221a" },
  "arrival": { "role": "observer", "level": "glance" },
  "files": [
    { "path": "assignment.html", "view": "assignment", "bytes": 20114, "sha256": "…" },
    { "path": "context-4e2b.html", "view": "context", "task": "4e2b", "bytes": 30020, "sha256": "…" },
    { "path": "queue-ada@example.org.html", "view": "queue", "person": "ada@example.org", "bytes": 12790, "sha256": "…" }
  ]
}
```

`files` lists every file but the manifest, sorted by the bytes of `path`; an asset has no `view`. The keys stand in the order shown, the indent is two spaces, the file ends with one newline, and `&`, `<` and `>` stay unescaped.

**The date is the commit's, never the clock's.** No file holds the time of the export, the host's name, a path outside the bundle or a random value. The audit counts a status stale against the commit's author date (A9, D8), so the audit page of a commit does not change with the day someone exports it.

**The same commit gives the same bytes**, under four conditions the manifest and the clone make checkable: the same `tableaud` and `tablo` versions, the same text after `--ref`, the same trunk commit, and a clone that holds the full history and the subprojects. The trunk matters because authorisation reads the trunk whatever the ref (VIEWS.md, Parameters): the bundle of the trunk's own tip depends on that commit alone, which is the case CI publishes, and the bundle of any other commit changes when the trunk moves. A shallow clone shortens the history and a clone without its submodules adds audit findings (J8), so the CI job fetches both, as design 1422 of tabloio has its job do. The export renders the pages one after another in the order of their paths and sorts every list it writes; time zone, locale and working directory do not enter.

### What needs a server, and what the export does about it

| The daemon offers                                                         | The bundle                                                                                                                              |
|---------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------|
| HTMX: a fragment fetched on expansion, a poll for a changed project       | None. Each page holds glance, detail and provenance in native `details`; no page holds a `script`, an `hx-` attribute or a poll (A4). No copy of HTMX enters the bundle |
| An arrival state per viewer: open blocks, marked cells, the viewer's corner and queue | One arrival: the observer's, at glance, no cell marked. The lists stand in for "my" corner and queue (D1, D4)             |
| A column choice the browser keeps and the link carries                    | The default window only; a folded column shows its count. The page draws no column control                                              |
| A link that carries an expansion, so a page opens as its sender saw it    | A link names a page and an element in it, no more                                                                                       |
| A query for any window, range, stale age, role, level or person filter    | The default of each                                                                                                                     |
| A task page of a subproject, read at its pin                              | None; the subproject publishes its own bundle (D2)                                                                                      |

### The bundle check

`Check` reads the files the export is about to write and reports each breach of what the bundle promises. The export runs it over every bundle and writes only when it reports nothing; the tests and the view templates' own tests call the same function. It parses each page with `encoding/xml` in its lenient HTML mode (`Strict` off, `HTMLAutoClose`, `HTMLEntity`) on `RawToken`, keeping its own stack, so the module gains no dependency; a trial of this reader parses all ten mockups and the prototype's bundle.

| Rule       | Reports                                                                                                                                            |
|------------|----------------------------------------------------------------------------------------------------------------------------------------------------|
| `parse`    | A page the reader cannot read to its end, or whose elements do not close in order; a file that is not valid UTF-8                                     |
| `script`   | A `script` element, an attribute whose name starts with `on`, a `javascript:` address, an asset named `.js` or `.mjs`                                |
| `htmx`     | An attribute whose name starts with `hx-` or `data-hx-`                                                                                             |
| `control`  | A `form`, `button`, `input` or `select`, or a `textarea` without `readonly`                                                                         |
| `embed`    | An `iframe`, `object`, `embed` or `base` element, or a `meta` with `http-equiv`                                                                     |
| `css`      | `@import` or `url(` in a `style` element, a `style` attribute or a `.css` asset                                                                     |
| `absolute` | An address with a scheme or a host, or one that starts with `/`, in `href`, `src`, `action`, `formaction`, `poster`, `data`, `srcset` or `cite`      |
| `query`    | An address with a `?`                                                                                                                              |
| `outside`  | A relative address that climbs out of the bundle                                                                                                   |
| `missing`  | An address whose file the bundle lacks                                                                                                             |
| `fragment` | A fragment that names no `id` in its target file                                                                                                   |
| `id`       | An `id` that occurs twice in one page                                                                                                              |
| `orphan`   | A file other than `manifest.json` that no chain of links reaches from `index.html`                                                                 |

A read-only `textarea` passes because it needs no server: the queue mockup holds the brief in one, for copying. An absolute address that a page shows as text, a reference or a `git` command, passes: the rules read attributes.

### Writing

The export renders every page into memory, runs the check, builds the manifest, and only then touches the disk. It creates the output directory when absent, and `static/` when an asset needs it, writes each file once in the order of its path with mode 0644, and writes `manifest.json` last, so a bundle with a manifest is complete. It creates no temporary file, no parent of the output directory and no file anywhere else, and it changes nothing in the repository. If a write fails it removes the files it wrote, removes the directory if it created it, and exits 3.

### The packages

`cmd/tableaud` gains the `export` word in the dispatcher the Server lands (A1). All else is one new package, `internal/export`, which imports `internal/web` and never the reverse.

```go
// Package export writes the static bundle.
package export

// View names one of the ten views by the stem of its mockup file. The ten
// constants are Tableau, Context, Queue, Blockage, Task, Assignment,
// Authority, History, Audit and Gates, each with its name in lower case as
// its value.
type View string

// Target is what a link names: a view, its focus and an element in the page.
// Every other parameter of the daemon's address has no place in a bundle.
type Target struct {
	View     View
	Task     string // a task id, or empty
	Person   string // an email, or empty
	Project  string // the url of the subproject that holds the task, or empty for this project
	Fragment string // an element id without the #, or empty
}

// Rev is the commit in view.
type Rev struct {
	Name        string    // the ref as given
	Commit      string    // forty hexadecimal digits
	Date        time.Time // the commit's author date, in the zone the commit records
	Trunk       string    // the trunk's name from version.yaml
	TrunkCommit string    // the commit the trunk stands at
}

// TaskRef is one task of the index.
type TaskRef struct {
	ID, Title, Parent string // Parent is empty for the root
	Children          int
}

// Index lists what the bundle makes a page for.
type Index struct {
	Tasks  []TaskRef // in display order; Tasks[0] is the root
	People []string  // emails, sorted by their bytes
}

// Linker answers a template that asks for an address.
type Linker interface {
	// Href gives the address of a page, or false when the medium holds none
	// and the template writes the text without a link.
	Href(t Target) (string, bool)
	// Asset gives the address of a file under the embedded static directory.
	Asset(name string) string
	// Reference gives the address of a url from a task file or of one of the
	// method's texts, or false when the medium links none.
	Reference(url string) (string, bool)
}

// Site is the part of the Server the export drives. Each method renders for
// a reader with no email, at glance, with every level in the page and with
// nothing that needs a server.
type Site interface {
	// Resolve names the commit a ref stands at.
	Resolve(ref string) (Rev, error)
	// Index lists the tasks and the people of the project at rev.
	Index(rev Rev) (Index, error)
	// Render writes the whole page of one view, taking every address from links.
	Render(w io.Writer, rev Rev, t Target, links Linker) error
	// Frame writes body inside the chrome every view shares, with current
	// marked in the navigation.
	Frame(w io.Writer, rev Rev, current View, title string, links Linker, body template.HTML) error
	// Asset reads one file of the embedded static directory.
	Asset(name string) ([]byte, error)
}

// Options is one run.
type Options struct {
	Out      string // the output directory
	Ref      string // the text after --ref; "HEAD" when absent
	Tableaud string // this binary's version, for the manifest
	Tablo    string // the tablo version in use, for the manifest
}

// Result is what the command prints.
type Result struct {
	Files int
	Bytes int64
	Rev   Rev
}

// ErrRefused marks an error that exits 1; any other error exits 3.
var ErrRefused = errors.New("export refused")

// Run exports the project that site reads. It writes the bundle or nothing.
func Run(site Site, o Options) (Result, error)

// Finding is one breach of what the bundle promises.
type Finding struct{ File, Rule, Detail string }

// Check reports every breach in a set of files keyed by bundle path, sorted
// by file, rule and detail. An empty result means the bundle holds.
func Check(files map[string][]byte) []Finding
```

Inside the package, one function each: `plan(Index) ([]page, error)` lists the files and their targets in path order and refuses a name clash; `slug(email string) string` writes a person for a file name; `paths.Href`, `paths.Asset` and `paths.Reference` implement `Linker` over the plan, record the assets asked for and answer every reference with false; `chooser(view View, ix Index, links Linker) (template.HTML, error)` executes `choose.html` for one of the three lists; `manifest(...) []byte`; `write(dir string, files map[string][]byte, manifest []byte) error`.

### From the prototype

The design keeps what [prototype 6160](../prototype/6160/README.md) settles: native `details` over fragments and over a page per state (its question 1), the linker as the one place where the daemon and the export differ (question 3), rendering in memory before any write, the manifest with sizes and SHA-256, the refusal of a non-empty directory, and its link walk, relocation and determinism tests. It drops the `fragments` and `states` modes with `--mode`, `--data` and `--estimate`; the nested layout with its `..` arithmetic, for the flat one the prototype's finding 2 points at; the index page that lists every file, for the tableau and the three lists; the page per person for the assignment, which the mockup draws as one page; and the staging directory beside the output, which writes outside it. Of its findings, 1 is A4, 4 is rule 9 and D6, 5 is D7 and 6 is A7; 3 falls away with the fragments; 8 stays with the templates; 7 is accepted: a bundle links a page and an element, not an expansion.

## Conformance to the texts

The export draws no view; the templates do (438a, e2b6, 44bf, 9a9c). It fixes which form of each view a bundle holds. In every page the glance stands open, each detail sits in a `details.detail` and each provenance in a `details.prov`, as the mockup draws them, and all are closed: VIEWS.md opens glance for "every role on a static export", and README.md gives the observer the export "where the observer has no tool".

| Task definition        | Task definition        | `task.html`       | One page per task, no person marked                                                             |
| Authority delegation   | Authority delegation   | `authority.html`  | The whole tree; the proposed tasks as the section the mockup draws                              |

| Global tableau         | Global tableau         | `tableau.html`    | The glance grid and, folded, the whole grid, as the mockup's note on a static export says; the default window |
| Contextual tableau     | Contextual tableau     | `context.html`    | The task form per task with children and the person form per person, each in its own default window |

The two owner's rulings hold without work here: the window reaches the two tableaux only, through their own defaults, and the export never turns the historical junctions on.

**The mockups against a static bundle.** The mockups claim to work as a static export: native `details` and `summary`, plain relative links, no script. The check agrees on the last two counts and on every fragment: the ten files hold no `script`, no event attribute, no absolute address, no image, font or stylesheet link, and all their fragments resolve. [`6160/mockups.tsv`](6160/mockups.tsv) lists what remains by file, rule and count, 700 findings of three rules, and reading the notes adds the rest. A static bundle cannot honour:

1. **The query links**, 667 of them: `task.html?task=e9c6`. A file system and a static host drop the query, so every one opens the same file, as `task.html` itself notes. The bundle writes `task-e9c6.html`.
2. **The links to another project**, eleven in `task.html`: `task.html?task=8608&project=subprojects/tableaud`. Prototype 49ce names no `project` parameter either (D2, finding).
3. **The links that mean "mine"**: `context.html` and `queue.html` in the navigation, which the daemon answers for the viewer.
4. **The links with no task**: `task.html` in the navigation, in the thirty-seven per-task links of `authority.html` and beside an id twenty-three times in `blockage.html`, where the mockup leaves the task out. The daemon of prototype 49ce answers these with 400 (finding).
5. **The links that leave the directory**, eight: `../../README.md`, `../../PLAN.md` and `../../corpus/RULES.md` in `audit.html` and `task.html`, the method's texts as the rule behind a finding (rule 9, D6).
6. **The column controls**: eleven `button` elements in `tableau.html` and the form in `context.html`, fourteen findings with its inputs and its button. Their own notes say the daemon redraws the grid, keeps the choice in the browser and carries it in the link.
7. **The arrival of a viewer**: 107 `details` stand `open` for the owner, cells and emails carry the viewer's mark, and each context line names the viewer and the role.
8. **Unfolding in place**: `tableau.html` and `context.html` say the daemon unfolds a parent in place and its link carries the open rows, and that script moves a parent's children into the grid.
9. **Parameters as pictures**: the history's range `0704a09..main`, the audit's one person, the tableau's variations. A bundle holds the default of each.

The read-only `textarea` in `queue.html` and every `details` need no server and stay.

**The open points.** The file names carry no query name, so the export does not wait for the names the Server and the templates settle. For the person default that "does not fit every view", this design answers for the static medium only: a view that needs a person and has no viewer lists the people (D4); the daemon's answer stays with 49ce.

## Assumed interfaces

These are assumptions. Where a neighbour's accepted design names a thing otherwise, the implementation takes the neighbour's name, and the behaviour above stands.

## Decisions at review

The owner decided each question this design raised on 2026-10-06, together with the cross-design rulings of that review; a decision the review did not reach stands as the design states it, accepted with the design.

1. **The arrival.** Accepted with the design, as stated: the export freezes the observer's arrival at glance, with no viewer and no option to change it, as VIEWS.md and the mockups' notes state. The alternative is an `--as <email>` that freezes that person's arrival and marks, which waits for db74 and makes a bundle one person's.
2. **One project per bundle.** Accepted with the design, as stated: a task of a subproject gets no page, and a link to one prints as text; each subproject publishes its own bundle. The alternative nests a bundle per recursive junction, read at its pin, which gives this plan 240 files and puts a second directory level under every link.
3. **The flat layout and the front page.** Accepted with the design, as stated: every page sits at the root under `<view>-<focus>.html`, and `index.html` is the global tableau, with no `tableau.html`. The owner ruled that a link's form belongs to the medium, so the mockups' `task.html?task=…` links stay as drawn and VIEWS.md's log says why. The alternative keeps `tableau.html` and gives `index.html` to a page that lists every file, as the prototype does.
4. **Three pages no mockup draws.** Accepted with the design, as stated: `task.html`, `queue.html` and `context.html` list the tasks and the people, in the shared chrome and the shared style. The alternative points "Task" and "My corner" at the root's pages and leaves the queues to the links of the assignment page. This answers the open point on the person default for the static medium, and binds this design alone; the person default of the live tools is the viewer on the queue and on the contextual tableau without a task alone (5ca9 decision 3).
5. **A history per task.** Accepted with the design, as stated: every task but the root gets `history-<id>.html`, about a third of the bytes. The alternative writes `history.html` alone and lands every task's history link on it.
6. **No address leaves the bundle.** Accepted with the design, as stated: a task's reference and the text of a rule print as text, even when the `url` is absolute, so that no page holds an absolute address. The alternative allows `https:` in the `href` of an `a` alone: a reader then follows a reference, and a page still loads nothing from outside.
7. **The default window, and no flag for it.** Accepted with the design, as stated: the tableaux show the default window and nothing unfolds a column. The alternative gives `export` the window, columns and historical flags under the names tabloio's Read commands (5ca9) settle, as PLAN.md has CI fix them once for Markdown.
8. **Staleness counts from the commit.** Accepted with the design, as stated: the audit in a bundle counts seven days back from the commit's author date, so the same commit gives the same page; it binds tablo's Audit (dada) through A9, and passes the date through tablo's `--now` (4ed9 decision 7). The alternative counts from the day of the export, which no second run reproduces.
9. **The check refuses.** Accepted with the design, as stated: a finding fails the export with exit 1 and no bundle. The alternative writes the bundle and reports the findings as warnings.
10. **No staging, no replace.** Accepted with the design, as stated: the export writes straight into a directory that is absent or empty, so it writes nowhere else; a crash leaves a bundle without `manifest.json`. The alternative stages in a sibling directory and renames, which is atomic and writes outside the output directory.
11. **The option's name.** Decided by the owner on 2026-10-06: the ref option is `--ref`, in every tool (4ed9 decision 3); the text reads so throughout, where this design was written with `--at` as tableaud's README and the Server's prototype named it. The README changes now. The export's folds follow the shared rulings through 438a: the count in the header, parents included, and a long list folding from more than eight alike rows.
12. **The linker's names.** Decided by the owner on 2026-10-06, at the Server's implementation review: `web.Linker` is the Server's, with `Page(Link) string`, the empty string where this design's `Href` returned false, `Static` for `Asset`, and `Reference(url) (string, bool)` as a required method, so the export's rule for an absolute address is a method it must write and not a default it may fall into. `Site.Render` and `Site.Frame` are `web.Render` with a `Shape`. The index of tasks and people A7 needs has no source yet. `prototype/6160/` goes when this task records `implementation`, as the README now states of every prototype.
13. **The reconciliation with the server as built.** Proposed on 2026-10-07, awaiting the owner: [`438a/server.md`](438a/server.md) completes decision 12. `export.View`, `Target`, `Linker`, `Site`, `Rev`, `TaskRef` and `Index` do not land: the unexported `paths` implements `web.Linker` over `web.Link`, the fragment is the caller's to append, and `Run` takes a `source.Source` and calls `web.Render` as a `Document` with `Scripts` off. The server gains, with this task: `Source.Index` with `source.Index` and `source.IndexTask`, which answers A7; `Page.Raw`, which draws the three lists inside the frame (A5); and a guard in `base.html`, which writes `hx-target` and `hx-swap` on `<div id="page">` whatever `Scripts` says and so breaks the `htmx` rule today. The command reads `tableaud export [-C DIR] --out DIR [--ref REF]`, as `serve` takes `-C`. Each page's context line reads "viewer: an observer", the frame's words, where A6 prints no viewer. T1, T4, T6, T7, T13, T15 and T16 change their wording.
